# Графические патчи — стандарт разработки (2026-11-25)

Владелец одобрил идею отдельных патчей. Это правило процесса, не автоматическая приёмка EM080, не разрешение на релиз или изменение main.

## Контракт
- Выбрать точный базовый commit и рабочую ветку, зафиксировать границы задачи. Не трогать принятую механику, исходную модель и неизменяемые ресурсы.
- Рендерить в локальной вычислительной среде агента. Разделять кузов, подвижные детали, окраску, тени и эффекты. Проверять реальные 3D-рендеры, а не рисовать заменители геометрии.
- Патч — ZIP входных игровых ресурсов для сборщика, не установщик и не Windows Updater. Включать только изменяемый согласованный набор путей относительно корня мода; допускается целый согласованный комплект спрайтов объекта, включая неизменённые связанные слои, как в EM080. Исходники рендера, логи, сравнения, QA хранить отдельно.
- Зафиксировать SHA256 ZIP и каждого PNG, список путей, размеры, число направлений, режим RGBA, pivot и версию базового контракта. Сверять хеши машинно; не перепечатывать вручную без повторной проверки.
- До применения проверять точный базовый контракт, отсутствие лишних, пропущенных, дублированных или небезопасных путей, целостность ZIP и всех ресурсов. Только после полного PASS помещать файлы в staging сборщика. Запрещены неявная подмена старой графикой и автоматический повторный рендер.
- Кодовые изменения, если требуются для подключения слоёв, делать отдельным ограниченным изменением исходников и покрывать регрессией; проверять неизменность механики. Прототипы, маски, эффекты и ресурсы должны соответствовать друг другу.
- GitHub Actions проверяет полный итоговый manifest, Lua, упаковку и выдаёт официальный полный ZIP. При отсутствии входного патча — BLOCKED, не считать пропущенную упаковку успехом. Отдавать пользователю ссылку на точный CI artifact и фиксировать commit, run, artifact, SHA256 внутреннего ZIP. Не создавать локальный установочный ZIP, не восстанавливать retired Windows Updater.
- При ограничении передачи бинарных файлов сначала использовать доступный разрешённый механизм; если невозможно — один точный архив и ссылка на целевую папку для ручной загрузки. Не просить пользователя повторять уже выполненную загрузку.
- При неудаче сохранить базовую версию и журналы, исправить только ошибочный слой/код, выпустить новый именованный кандидат. Не перезаписывать принятую сборку. Приёмка в игре отдельно от PASS локального рендера, mock-тестов и CI. Никаких merge/release без отдельного разрешения.
