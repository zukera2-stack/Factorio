## Условия
Два обычных `small-electric-pole`, два штатных `electric-energy-interface` из Base, оба на одной обычной поверхности. Источник `secondary_output`, приёмник `secondary_input`, ёмкость каждого 2 МДж, power_production=power_usage=0. Вход источника и выход приёмника выключены; приёмник запрашивает 200000 J/tick (кроме no-load). На t121 в источник записано ровно 100000 J, output_flow_limit=100000 J/tick. Все остальные источники отсутствуют. На t120 проверены нулевые буферы и принадлежность интерфейсов к соответствующим опорам. Сценарий проверяет баланс при t122/123/128 с допуском 0.05 J, итоговые буферы, завершение native test at t129.

## Интерпретация
Результат EM094A по соединению скрытых портов воспроизводит штатный native EEI transport при изменении сети, а не физическую утечку между остающимися изолированными сетями. Само объединение разрешённых контуров не дефект. Нельзя считать старый electric_network_id неизменным разрешением на весь интервал; важно различать допустимое объединение/разделение от запрещённого соединения (например, обхода преобразователя 25 кВ/заводской сети). Учёт уже фактически отданных J нельзя превращать в повторный возврат накопителю только потому, что изменился ID сети. Предлагается пересмотреть блокер EM094A как неподтверждённый риск штатного gameplay, сохранив отрицательный тест искусственного запрещённого соединения. Контроль не доказывает безопасность обычных операций на нашем моде; строительство здесь выполнено API с auto_connect, не ручным GUI. Проверка 25 кВ/force/surface, lifecycle, pending save/load/disable и полной смешанной системы остаётся открытой. Никаких новых утверждённых решений или изменений production runtime.
