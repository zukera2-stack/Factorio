# Asset Workshop — источник → переделка → игровые спрайты

**Правило с 25.11.2026:** при запросах владельца на графику агенты применяют [скилл](../../.agents/skills/factorio-assets-from-reference/SKILL.md). Проект использует референсы именно существующих ассетов; генеративные идеи не выдаются за геометрически точную перерисовку. Для передачи в игру действует [Direct Patch](DIRECT_PATCH_WORKFLOW.md).

## Решённая проблема

В EM086 владелец запросил грузовой моторный вагон и цистерну **на основе ванильных вагонов** с моторной тележкой от утверждённого электровоза. Первые изображения создали новые вымышленные локомотивоподобные корпуса/пассажирскую электричку, потому что вместо существующих пикселей использовался текстовый промпт. Рабочим примером стал 2D repaint одного реально снятого в Factorio грузового вагона из скриншота. **Этот эскиз всё ещё не игровой набор PNG**. Исправление процесса: источник до рисования, не наоборот.

## Как выполнять любой запрос

1. Назови конкретный объект Factorio и класс результата: `study`, `concept`, `repaint`, `sprite-candidate` или `direct-patch`. В запросе «перекрасить ванильный» класс только `study` при отсутствии ванильного многокадрового PNG.
2. Прочти реальные игровые прототипы/спрайт API, найди оригинал (`__base__`, собственный репозиторий, Library, пользовательские файлы) и сделай source manifest с SHA256. Отсутствие Base art в Linux Headless — реальный блокер, не разрешение выдумывать контент.
3. Проверь лицензионную возможность распространять основанный на Base PNG файл. Для несогласованных источников используй Base ref или оригинально нарисованный комплект. Не загружай чужую графику в игровой ZIP без оснований.
4. Сделай один честный эскиз **до/после одного и того же ракурса**, без декоративного постера. Для `repaint` альфа исходника и целевого PNG должна совпасть пиксельно; для компонента нужны отдельно измеренные pivot/размер/тень.
5. Технический sprite-candidate: atlas sizes, named layers, mask/shadow, `direction_count`, `line_length`, `lines_per_file`, `shift/scale`, native entity bounding/joint geometry, transparent pixels, 256/8/прочие направления — берутся из реального прототипа. Не превращай один screenshot в 256 фальшивых ориентаций.
6. Запусти `scripts/assets/qa_sprite_edit.py` и сохрани JSON QA вне `ElectrifiedMainline/`. Для полного мода запускай **нужные** Lua+native Factorio тесты; Headless не проверяет художественное качество.
7. Выдай явно подписанный preview. После тестов сформируй **Direct Patch** только из изменённых файлов и `info.json`, отдельный manifest, QA и versioned `from→to` по [стандарту](DIRECT_PATCH_WORKFLOW.md); визуальная приёмка в Windows остаётся за владельцем.

## Файлы

- `.agents/skills/factorio-assets-from-reference/SKILL.md` — инструкция для нового агента, триггеры и ограничения.
- `.agents/skills/factorio-assets-from-reference/references/{asset-contract,request-template}.md` — доказательность, обязательные слои и компактный шаблон задания.
- `scripts/assets/qa_sprite_edit.py` — проверка прозрачности/альфы/размеров/кадров с машинным JSON отчётом.
- `tests/test_asset_workshop.py` — синтетические smoke/regression тесты, не заменяют реальные игровые.
- `.github/workflows/asset-workshop-checks.yml` — CI только для инструмента/скилла, **без сборки, рендера и релиза мода**.
- `/Factorio/References/Motor-Wagon-Vanilla-Sprite-Studies/cargo_actual_screenshot_before_after_2d_preview.zip` — owner screenshot comparison study (не runtime) в GPT Library.

## Что сохраняется

`main` и текущие слои электровоза V3/EM082/EM083 не изменяются данным навыком. Физика моторных вагонов EM084/EM085 не меняется. Собственные новые PNG и Lua должны появляться только в отдельной задачной ветке и после установления исходников.
