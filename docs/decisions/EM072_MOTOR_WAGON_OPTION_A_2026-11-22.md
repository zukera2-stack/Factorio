# EM072 — решение автора: вариант А, вагоны остаются вагонами

**Дата:** 2026-11-22. **Статус:** выбран подход А для будущей разработки и задано ограничение: **не использовать топливные множители ради моторизации и не менять скорость поезда скриптом**. Это НЕ утверждение конкретного работоспособного механизма, который ещё предстоит доказать.

## Утверждённые свойства

1. Моторные грузовой и жидкостный вагоны обязаны остаться штатными типами `cargo-wagon` и `fluid-wagon`, сохраняющими родные инвентари, насосы/манипуляторы и сцепку.
2. У них **нет аккумуляторов или прямого пантографа**, но есть проектный добавочный тяговый вклад +500 кВт на моторный вагон. Батареи/защищённый резерв принадлежат только электровозам; несколько локомотивов делят энергию по логической шине состава.
3. Желаемая формула на пуске: `P_nameplate = 2MW*N_loco + 0.5MW*N_motor_wagon`; суммарная **расчётная** мощность — не автоматически физический атрибут одного локомотива.
4. Автор предложил менять `max_power` локомотива на ходу при изменении состава, без каких-либо топливных модификаторов. **EM072-C2 native Factorio 2.1.24 REJECTS this direct runtime API mechanism**; см. [отчёт](../research/native-locomotive-runtime-maxpower-072c2.md).
5. Прототипы с заранее заданным `max_power` действительно по-разному разгоняются, но runtime переключение прототипа у сущности невозможно простым присваиванием: `loco.prototype` доступен только для чтения. **Замена физической сущности** ради 2/3MW могла бы изменить unit_number, сцепку и сохранение батареи, это ещё не реализовано, не протестировано и **не одобрено в качестве gameplay-решения**.
6. Лабораторный `VoidEnergySource` нужен только для сравнения разгона. В игровом моде оплачиваемая тяга **не может питаться от void**, иначе энергия бесконечна. «Без топливных множителей/видимого игрового топлива» не означает разрешения создавать бесплатные джоули; способ допустимого конечного энергопитания ещё требуется выбрать по техническим доказательствам.

## Текущий этап

Ветка исследования: `experiment/em072-c2-maxpower-runtime-api`; оригинальный `main` ElectrifiedMainline 0.1.62 не меняется. Открыт **технический блокер** прямого `loco.max_power += 500000` в runtime. Продолжать независимые API/эксперименты, не выдавать +500 кВт моторов вагона за работающий игровой механизм. При необходимости замены сущности или изменения исходного типа вагонов — отдельное явное решение автора.
