# EM072 — полный нативный источник 120 МВт для 200 моторных вагонов (0.1.72)

**Эксперимент от 2026-11-23. Не релиз, не main, не замена утверждённой 20-МВт тяговой подстанции.**

Пользователь потребовал испытать номинальные 100 МВт дополнительной тяги от 200 настоящих моторных грузовых вагонов, а не ограничиваться источником 20 МВт. В экспериментальной полной 0.1.72 я добавил в тестовый мир настоящую Factorio сущность `electric-energy-interface` в native режиме `primary_output` с `power_production=120000000/60` и `output_flow_limit=120000000/60`, исходно `energy=0`.

В исходной 0.1.71 были **четыре разных ограничения 20 МВт**. Чтобы источник действительно доходил до поезда, увеличены только в отдельном исследовательском варианте:
- `prototypes/power_bridge_058.lua`: native EEI bridge input и output до 120 МВт, их промежуточные буферы 333334 J → 2 MJ.
- `scripts/power_bridge_058.lua`: маршрутный лимит `20e6/60` → `120e6/60` J/tick.
- `prototypes/traction_native_consumer_068.lua`: 25кВ secondary-input sink 20 → 120 МВт.
- `scripts/traction_paid_065.lua`: разрешённый native sink input cap 20 → 120 МВт.

Никакой скрипт QA не создаёт скрытых локомотивов и не начисляет им Дж. Все вагоны, подстанции, сеть, контакт и движок штатные. Скрытый +100 МВт двигатель создаёт сам мод из 200 моторных вагонов и одного реального электровоза +2 МВт. Скорость `LuaTrain.speed` не присваивается. Все 83 графических PNG унаследованы неизменными.

На тике300 при 120МВт нативный потребитель сообщил `native_25kv_demand_J_tick=1700000` (потребность 102 МВт в этот тик), а суммарный реально оплаченный дебет `paid_J=290966666.667` и моторный `motor_paid_J=283333333.333` к этому моменту. Не называть 102 МВт наблюдённой постоянной подачей: это **запрошенная** мгновенная мощность.

На том же новом высокомощном полном моде отрицательные сценарии `zero` и `offgrid` PASS: 0 Дж, 0 клеток, нет самодвижения. Сценарий `single` на источнике20 МВт также PASS.

## Ограничения

- Увеличение 20МВт →120МВт произведено **в существующих прототипах подстанции на изолированной опытной ветке**, а не через отдельный новый предмет для игрока. Это доказывает пропускную способность, но не является принятой энергетической архитектурой игрового релиза. У пользователя остаются его старые 20-МВт подстанции.
- Нет автоматического 120-МВт генератора в рецептах. Испытательный генератор native `electric-energy-interface` задаётся сценарием для воспроизводимости. Для игрового дизайна позже можно реализовать отдельную высокомощную подстанцию или суммирование нескольких существующих мостов по 20 МВт.
- 120 МВт >= номинальные 102 МВт состава с одним электровозом. Нельзя обещать, что поезд будет постоянно потреблять 102 МВт; native физика распределяет нагрузку во времени.
- Исследование никак не исправляет прежний **FAIL обратной дополнительной моторной тяги** в двухголовом составе.
- Windows GUI/Undo, реальный MP, UPS и пользовательские сохранения в этом испытании не проверены. CI ZIP не заменяет native game тест.

Отдельный сценарий `tests/em072-integration-qa/scenarios/native/control.lua` воспроизводит `long200high`, `long200high20`, `zero`, `offgrid`, `single`; `tests/run_em072_120mw_native.sh` использует настоящий полный ZIP и Factorio 2.1.24.
