## 2. Проверяемое поведение
Две настоящие подстанции `em-35kv-traction-substation` стоят на **одном непрерывном HSR** (в отличие от двух раздельных B6) и соединяются через технический граф с **одной общей контактной native electric network**. У каждой EM070 своя **независимая factory electric network** с 84 настоящими конечными аккумуляторами. Реальные 16 независимых `LuaTrain.id`/LuaBurner требуют статически 2MW каждый (итого 32MW). Один native input-only meter обслуживает все 16 через реальный script-owned 25kV terminal; **коридорных аккумуляторов в B8 специально нет**: проверяем мосты, а не буфер.

## 3. Приёмочный и отрицательный тест
1. Нативно проверить четыре электрические точки: A factory, B factory, A line-port, B line-port. **Factory A и Factory B не связаны напрямую и имеют разные `electric_network_id`; оба line-port и все мачты на одном HSR имеют один и тот же native network ID.**
2. Измерить `r.planned_mw` по каждой EM070 и реальные source-backed J из `M.transfer` (обязательно разделять import/export и показывать signed net), не приписывать 20MW плана фактическому потреблению.
3. До перегрузки при 16×2MW=32MW и двух 20MW станциях обе EM070 должны реально импортировать >0 J. Все 16 реальных burner-locomotives должны иметь неповторяющиеся LuaTrain ID, получать fair J и продвинуться по настоящим HSR без записей в `train.speed`.
4. На тике260 включить **именно на заводской сети ВТОРОЙ EM070**, координаты нагрузки `(500,23)`, настоящий нативный **30MW EEI secondary-input**. Жёстко подтвердить `load.electric_network_id == factory_B.electric_network_id`, иначе опыт недействителен. B native factory cells способны отдать лишь **25.2MW**. Контроль фактической выдачи и brownout; никаких скрытых генераторов, изменение аккумуляторных J в цикле запрещено.
5. **AUTO:** позволить EM070 самостоятельно выбрать направление. Отдельно измерить возможный экспорт из общей контактной сети в дефицитный завод B и его влияние на J 16 локомотивов.
6. **MANUAL IMPORT counterfactual:** изменить режим только B при включении B-заводской нагрузки на t260 на штатный manual `import`. Это альтернативная политика **только тест**, а не скрытый фикс игрового AUTO.
7. Посчитать **один общий замкнутый ledger:** 168 native source аккумуляторов + все EEI обоих мостов + corridor input meter + заводской native consumer + остатки LuaBurner + реально израсходованная энергия каждого двигателя и заводского потребителя. Раздельные леджеры двух заводов неверны, так как они связаны через общий мостовой компонент!
8. Каждый вариант: native **500 ticks PASS** и настоящий сервер SAVE t300 → **независимый процесс LOAD +200** с точным совпадением метровых и энергетических показаний. Нельзя считать успехом работу только статической Python-модели.

## 5. Дифф механики и API-ограничения
- Одна нативная контактная сеть отличается от B6 (двух электрически несвязанных линий); **не суммировать самодельные независимые ledger A+B**, когда нативная электроэнергия свободно пересекает обе стороны мостов.
- Обычный native accumulator сам по себе не является двухпортовым электрическим мостом. Соединение контактного meter обеспечено **зарегистрированным script-owned terminal через `wire_origin.script`**, тестовый whitelist — только в disposable копии.
- Расчёт энергопотока через `M.transfer` основан на реально накопленном J входного EEI, но направление учитывается **знаково**: при AUTO export `source` сети — контактная, а получатель — заводская.

## 6. Фальсифицируемая гипотеза и варианты
- Гипотеза: два EM070 не превысят 20MW каждой и смогут импортировать на общий контактный HSR ≥24MW при доступных factory sources; при заводском brownout одна из AUTO станций может сменить направление, но глобальная энергия сохранится.
- Отрицательные случаи: совпадающие factory network ID, разные line network ID при общем rail, native train не движется, M.transfer создаёт свободные J, полный ledger residual >3 J, SAVE→LOAD расходится — FAIL.
- Минимальный вариант: **не менять производственный алгоритм**, собрать целиком disposable стенд с нативными рабочими источниками и отдельным счётчиком `true_import_J / true_export_J`.
- Авторская развилка: чей спрос приоритетнее на мосту в AUTO при одновременном дефиците factory и train — промышленного завода или тяговой сети? Принудительное import демонстрирует альтернативу, **но не является утверждённой политикой**.
