## Нативная схема и корректные измерения

- **Один физически непрерывный HSR** (`y=1`) между двумя действительно размещёнными `em-35kv-traction-substation` EM070 (A `(-20,9)`, B `(500,9)`). Все мачты и оба `line_port` находятся на **одном родном электрическом `electric_network_id`**, что проверено внутри Factorio. Реальные заводские сети A/B имеют **разные** native network ID и не соединены друг с другом напрямую.
- Каждая фабрика получает **84 обычных vanilla accumulator** по 5MJ с пределом 300kW: всего 168 штук, **420MJ начального запаса и 25.2MW нативной разрядки на каждый завод**. У обеих EM070 предел 20MW. Нативных аккумуляторов **в контактной сети в B8 нет** — исключаем их влияние при проверке встречного импорта и экспорта. Есть один авторизованный тестовый script-owned terminal и один native 32MW input-only EEI meter; всю переданную им энергию сначала реально выдаёт Factorio.
- **16 отдельных настоящих `LuaTrain.id`**, для каждого настоящее движение с `character.riding_state.accelerating`, native burner-locomotive; **никогда не присваивается `train.speed`**. Спрос фиксирован исключительно для лаборатории: 2MW на поезд, итого **32MW**. Тяговые J выдаются лишь после списания их из фактического конечного native `meter.energy` в `LuaBurner.remaining_burning_fuel`; нативный burner сам расходует энергию. Проверка HSR/force/surface обязательна. Штатный production `em-electric-locomotive` всё ещё питается через `void` — не считать тест интеграцией электромотора.
- **При t260**: на заводской сети **ВТОРОЙ станции B** у `(500,23)` начинает требовать 30MW отдельный **входной native EEI**. Нативный скрипт буквально проверяет `load.electric_network_id == station_B.factory_id`, и **не позволяет ошибочно проводить эксперимент с заводом A**. За короткий измеренный период после старта test нагрузка 30MW, а у B аккумуляторов native 25.2MW; дефицит подтверждён **217 тиками**. В test-only Lua только снимается реальный полученный J с finite consumer buffer, никаких виртуальных зарядок аккумуляторов.
- Учёт **`M.transfer`** проверяет **каждую направленную выдачу** (завод→коридор *gross import*, коридор→завод *gross export*, net); не подменяет действительный J значением `planned_mw`. В B7 уже исправлена тестовая ошибка изменения кэшированного `device_sample.data`: B8 использует копию.

**AUTO в ответ на нехватку заводской энергии сам перевёл станцию B в экспорт**, при том что поезда на общей контактной сети продолжали требовать 32MW. B действительно отдал своей фабрике **10.217MJ** нативно оплаченной энергии из HSR; фабричная нагрузка B получила на **38.494MJ больше**, чем при вручную выбранном Import. При Import тяговые native burner получили на **38.254MJ больше**, но **44.169MJ из всего полученного в режиме Import всё ещё находились в баках к концу теста, поэтому нельзя приравнивать весь выигрыш к уже израсходованной тяговой энергии или более быстрому движению. Оба варианта выполняют физический закон сохранения энергии; разница — выбранный адресат дефицитной мощности.

Одна большая **суммарная** ledger проверка складывает исходный finite запас 168 аккумуляторов, оба входных/выходных EEI обеих EM070, traction meter, фактический J native industrial consumer, оставшийся у 16 burner и реально сожжённый J. Когда есть две фабрики, соединённые через HSR обратным мостом, нельзя делать два независимых ledger — поэтому используется общий остаток практически 0J. Пределы 20MW относятся к отдельным EM070; native временный буфер EEI не является неисчерпаемой генерацией.

## Проверки повторения после SAVE → LOAD

Два разных полных запуска из нового пустого disposable мира, каждый в **реальном Factorio Headless**: `500 ticks` проверки, затем отдельное создание сервера, настоящий **SAVE t300** и независимый процесс **LOAD ещё +200 ticks**. В каждом варианте native-лог и reload дают идентичные J, plan/режим, расстояния и глобальный остаток. Автоматический runner проверяет исходный ZIP SHA256, 5 Git blob SHA, наличие настоящего Factorio build87808, настоящую native топологию, численные метрики и сохранение. Пример:

```bash
python3 tests/run_native_shared_072a5b8.py \
  --factorio /path/to/Factorio-2.1.24/bin/x64/factorio \
  --ci-game-zip /path/to/EM071-0.1.62-CI.zip \
  --output /empty/experimental-dir \
  --variant auto
```

Для альтернативы смените только `--variant manual_import`. 

**AUTO** (перепроверенный прогон): native log SHA256 `acc6c7f0c80afe789a2552c7fee3cfcb567765d872f5cd97d124c7fb45e3843d`, independent reload SHA256 `e1f580028108d4c47070f5be956720b1f27453c2754ceaaf351cb92d87fcb0fd`, реальный checkpoint 763,840 bytes.

**Manual Import** (перепроверенный прогон): native log SHA256 `0ead8da33296b2f5635b6203f0d4be35102fa600cbb5b5e67018e787a90af24d`, independent reload SHA256 `87ae8704b72ec28908f17888d798faa5cb0010ceb6a0740da7681c3d8ba5a26f`, реальный checkpoint 680,786 bytes. ## Негативные результаты, ограничения, решение автора

1. **Не «потеря» энергии:** AUTO отдаёт J в дефицитный завод B через реальный экспорт; global ledger =0 J. Встречный импорт/экспорт считается отдельно, а план EM070 не путается с реальной переданной энергией.
2. **Завод B, НЕ завод A:** раннее диагностическое сообщение тестового кода ошибочно называло factory A, несмотря на верную native проверку `load.electric_network_id == factory_B`. Надпись исправлена, оба прогона воспроизведены с новым исходником. Это проверка качества журналов; прежняя схема B8 не изменилась.
3. **Не тест реального игрового электровоза:** locomotives — настоящие движущиеся native burner entities, но тяговая заявка **постоянная 2MW/поезд**, а не динамика/рекуперация/моторвагоны +500kW; нет пользовательских Blueprint/Undo/сноса/постройки, нет multiplayer/большого мира и 60UPS stress, нет реальных коридорных native аккумуляторов в этом сравнении и нет подтверждения регрессий от Bob's/других модов.
4. **Не утверждён AUTO policy:** owner решает, резервировать ли электропитание для тяговой сети в ущерб заводскому brownout (выбирать Import при дефиците тяги) или штатно разрешать AUTO rescue промышленного завода даже при тяговом дефиците. Обе стратегии проверены как тестовые, **автоматически ничего не менять в production**.
5. Предыдущая отдельная развилка B7: `battery-first` vs `factory-first` для накопителей аванпоста остаётся открытой; B8 не содержит native corridor battery и не закрывает её.
