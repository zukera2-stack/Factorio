## 2. Тестовая конфигурация

- Один настоящий `em-35kv-traction-substation` EM070 в `AUTO`, реальный электрический мост 20 МВт; длинный непрерывный HSR путь из настоящих `em-high-speed-straight-rail`, 22 родные контактные мачты.
- 12 **независимых `LuaTrain.id`**, каждый содержит один настоящий `locomotive`-клон 2 МВт, нативный burner и водителя `character` с `riding_state.accelerating`. **Никакой записи `LuaTrain.speed`**.
- Источник: 84 штатных аккумулятора Base с 5 МДж каждый, **420 МДж конечного запаса, 25,2 МВт допустимой отдачи**; все 84 подтверждённо подключены к одному заводскому `electric_network_id`, который **не равен** контактной сети.
- Расчётная тестовая заявка: 12 × 2 МВт = 24 МВт, 400000 Дж/тик; EM070 физически ограничена 20 МВт, 333333,333 Дж/тик. Запросы собраны по реальной линии один раз, без умножения на число опор; доступность поездов проверяется родными HSR `get_connected_rail` и `LuaTrain.get_rails`; BFS выполнен **1 раз** и используется кэш.
- Фактически распределённая native EEI-энергия списывается в том же тике, когда добавляется в `LuaBurner.remaining_burning_fuel`. Max-min равномерность 12 потребителей проверена на каждом положительном тике. Её обеспечивает **исследовательский allocator**, не основной игровой код.

## 4. Границы доказательства

**B0 доказал только:** движение 12 настоящих локомотивов с фактически потраченной энергией, конечный фабричный источник, один реальный активный двусторонний мост EM070, справедливое распределение строго ≤20 МВт, электрическую изоляцию и диск SAVE→LOAD.

**НЕ доказано:** потребление реальным `em-electric-locomotive` (он пока имеет `void`); автоматическое вычисление запроса по движению/расписанию/ускорению (в опыте фиксирован запрос 2 МВт на каждый водительский локомотив); настоящие 12 одновременно получающие питание **от коридорного** аккумуляторного буфера; отключение станции и резерв; заводской brownout; 2+ компонента/станции; разделение/слияние поездов; аварийные разрывы; крупная карта UPS и multiplayer; мотор-вагоны +500 кВт; рекуперация.

Выдача джоулей выполнена из нативного **выходного EEI конкретной станции**, что подходит для B0, но **не подходит** для запланированного B5: при OFF станции надо питать от физически заряженных коридорных аккумуляторов через отдельный, пока не доказанный native потребитель/измеритель.

## 5. Воспроизведение

Использовать только официальный Factorio 2.1.24 Linux x86-64 и заранее скачанный **точно проверенный** GitHub Actions inner ZIP выше (не публиковать его повторно). Для исходников fixture запустить:

```bash
python3 tests/run_native_overload_072a5b0.py \
  --factorio /path/to/factorio/bin/x64/factorio \
  --ci-game-zip /path/to/verified/ElectrifiedMainline_0.1.62.zip \
  --output /tmp/em072a5-b0-fresh
```

`--output` должен быть пустой директорией. Runner сверяет SHA256, Git blob, игровую версию, запускает benchmark и независимый SAVE→LOAD, проверяет реальные маркеры/числа и сохраняет `result.json` и хэши журналов. Тестовый код/скрипты можно хранить в GitHub, **никакого установочного мода из этого PR нет**.
