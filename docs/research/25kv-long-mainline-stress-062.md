# 0.1.62 — нагрузочный тест длинной магистрали и заводских приоритетов

**Дата:** 2026-11-21. **Статус:** нативные игровые тесты выполнены; **обнаружен блокирующий риск производительности на 48 подстанциях**. Версия `test/updater-approved` осталась **0.1.61**; стабильная `main` осталась **0.1.56**.

## Точная проверяемая сборка

- Источник: `experiment/network-fair-share-062`, 0.1.62, результат PR #35, исходный runtime commit `53d8b188ed18a4fb2d320aa374956a45af34962c`.
- Испытывался **точный ZIP** из штатной сборки GitHub Actions 44885075734 (artifact 14699501754), `ElectrifiedMainline_0.1.62.zip`, SHA256 `8b3a22c6270afd676d7f451943feb61b2e5ba01060f4867628251098c8a977bb`.
- Реальный движок: Factorio Headless Linux x86-64 **2.1.24 build 87808**, загружен пользователем в личную библиотеку. Тестовые моды временные, **не входят в распространяемый ZIP**. **Bob's Power не установлен** в нативном стенде.
- Матрица: все заводские сети электрически изолированы друг от друга, но обслуживаются общей контактной линией. Электрический генератор — редакторский native EEI с `primary-output`, потребители — native EEI с `secondary-input`/`primary-input`. Фактическая энергия измеряется по native `LuaEntity.energy`, **не задаётся скриптом после начальной настройки**.

### Уточнение для теста с четырьмя источниками

Именно **четыре** источника находятся в позициях 1, 9, 17 и 25. Остальные 28 подстанций — потребители. После отключения чётных из 28 потребителей остаются 12 нечётных (позиции 1, 9, 17, 25 заняты источниками), а не 14. Это закреплено автоматическими проверками. На этапе распределения 80 МВт/12 = 6,667 МВт на приёмник.

## Критическая находка: падение производительности

Сравнение 48-узловых стендов с идентичной геометрией/нагрузкой и одинаковым 270-тиковым нативным benchmark на одном и том же headless-хосте:

| Метрика Factorio benchmark | 0.1.61 (жадный алгоритм) | 0.1.62 (новый справедливый алгоритм) |
|---|---:|---:|
| Среднее время одного обновления (включая создание карты на первом тике) | **40,708 мс** | **102,225 мс** |
| **Минимальное** время обновления | **3,121 мс** | **27,357 мс** |
| Максимальное время (однократное создание стенда) | 4985,824 мс | 4960,964 мс |
| Получатели с ненулевой энергией | Не все, часть голодает | Все 42, строго равные значения |

**16,667 мс/тик** — бюджет для 60 UPS. В этом сценарии даже минимальный тик 0.1.62 (27,357 мс) не помещается в бюджет; это тревожный показатель масштабирования, а не измерение производительности произвольной карты игрока. Это **блокирующий риск** перед продвижением 0.1.62 в патчер. Benchmark содержит единовременное создание большой карты и синтетические 42 EEI-потребителя, поэтому его среднее **не равно** прогнозу FPS/UPS на любой пользовательской карте. Однако сравнительная разница на той же конфигурации велика и требует оптимизации планировщика.

В исходном `bridge_dispatch_059.lua` новый честный алгоритм многократно вызывает поиск маршрута/проверку направленных циклов внутри вложенных циклов источников/потребителей. **Причина замедления пока инженерная гипотеза**: профилировщик вызовов не включался; не объявлять доказанным конкретный hot path.

## Правила приёмки и следующий шаг

1. **Не выпускать** текущую 0.1.62 в Updater 1.1 до устранения масштабного замедления.
2. Профилировать и оптимизировать `dispatch.plan`: уменьшить повторный BFS и проверки достижимости, сохранить доказанный равный раздел и отсутствие циклов, а также 20 МВт/станцию.
3. Перезапустить все уже существующие 062 тесты, 32-подстанционные нагрузки, тест защиты заводских потребителей и сравнительный 48-узловой benchmark против 061 **на одном хосте**. Строгая нативная функциональность — обязательна, performance gate — отдельный результат.
4. Не объявлять глобальную max-min fairness, Bob's Power native совместимость или потребление энергии электровозом подтверждёнными этим тестом.
5. Не изменять `main`, `test/updater-approved`, установленный мод пользователя или 83 проверенных PNG в рамках документации/QA.

## Воспроизведение локально

```sh
python3 tests/run_native_stress_062.py \
  --engine-bin /path/to/factorio/bin/x64/factorio \
  --game-zip /path/to/ElectrifiedMainline_0.1.62.zip \
  --out build/native-stress-062

# Отдельно — дорогая 48-узловая проверка и контроль на 061:
python3 tests/run_native_stress_062.py \
  --engine-bin /path/to/factorio/bin/x64/factorio \
  --game-zip /path/to/ElectrifiedMainline_0.1.62.zip \
  --include-48 --only em062-48sub-probe \
  --baseline-zip /path/to/ElectrifiedMainline_0.1.61.zip \
  --out build/native-stress-062
```

Скрипт проверяет версию Factorio и mod ZIP, создаёт и удаляет только **временные стенды**, пишет игровые журналы и машинный JSON. Никакого ручного вмешательства игрока не требует.
