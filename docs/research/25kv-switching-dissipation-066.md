# EM066 — физически обоснованное рассеяние при разрывах контактной сети

**Дата:** 21.11.2026. **Статус:** техническое решение и проверенный классификатор результатов EM065; **не исправление игрового кода и не разрешение на выпуск**.

## 1. Зачем пересматривать старое требование «ноль потерь»

Пользователь правильно заметил, что реальные электрические цепи при аварийном разрыве могут рассеивать запасённую энергию. Прежний тест EM064 с требованием *буквально нулевой* потери для любого действия слишком категоричен. Но равным образом неверно назвать всякое исчезновение энергии в программном буфере «физически допустимым»: наличие дуги, её время горения и расход энергии не моделируются автоматически одним фактом удаления мачты.

**Принятое ранее решение владельца:** при уничтожении подстанции исчезает **только энергия принадлежащих ей внутренних скрытых EEI**. Чужие подстанции и обычные аккумуляторы не получают права терять запас из-за этого удаления. Это действующее правило (EM064), а не новая гипотеза.

**Новое разделение:**

1. `E_external` — аккумуляторы, реальные источники, потребители: движок Factorio управляет их зарядом/разрядом. Не изменять их вручную ради бухгалтерии.
2. `E_handoff` — скрытые `electric-energy-interface` мостов (две пары терминалов); это **временные буферы алгоритма передачи**, а не измеренная ёмкость провода или батарея подстанции.
3. `E_line_field` — энергия электромагнитного поля контактной линии. **В текущем EM065 отдельной сущности, переменной и счётчика такого запаса нет**. Её можно ввести позже лишь с заданными параметрами длины, L, C, режимом питания и способом учёта.
4. `E_dissipated` — энергия, явно ушедшая в дугу, тепло, защиту, разрушенное оборудование. Разрешается учитывать только **фактически вычтенные** джоули с зафиксированными источником/причиной и ограничением по реальному запасу.

Система должна соблюдать закрытый баланс:

`E_initial + E_actual_input = E_remaining + E_consumed + E_dissipated + E_unaccounted`

В закрытом стенде EM065 новая генерация равна нулю, потребитель — накопительный EEI, поэтому `E_consumed` в нём тоже учитывается как сохранённый заряд. `E_unaccounted` должен стремиться к нулю; допуск округления теста — 4 Дж. Недостающие джоули нельзя переводить в `E_dissipated` задним числом только по названию события.

## 2. Что действительно происходит в высоковольтной линии

- Индуктивность хранит энергию магнитного поля, ёмкость — электрического. При размыкании возможны перенапряжения, повторное зажигание дуги и отвод энергии на разрядники/защитные устройства. **Необязательно, что весь остаток исчезнет мгновенно**: на изолированном участке возможен «запертый» заряд.
- Дуговой ток при наличии питания может дополнительно получать энергию **от генератора**, пока защита не отключила аварийный участок. Эту энергию нельзя путать с ранее накопленной энергией линии.
- Штатное размыкание и фактическое короткое замыкание — **разные события**. Даже для настоящих линий без модели напряжения, L, C, длительности дуги и защит определить единственно верную энергию рассеяния нельзя.

Источники для технического обоснования:

- U.S. Bureau of Reclamation, *Transmission Line Design Manual*, глава о switching surges: https://www.usbr.gov/tsc/techreferences/mands/mands-pdfs/TrnsLine.pdf
- NIST/NBS, *Line Conducted Disturbances — Origins and Control*, коммутационные перенапряжения: https://www.nist.gov/system/files/documents/pml/div684/NBS_Forum.pdf
- Исследование разряда линии после отключения: https://www.mdpi.com/1996-1073/17/4/799
- API Factorio, энергия и перевод Вт в Дж/тик: https://lua-api.factorio.com/2.1.24/types/Energy.html

### Иллюстративная оценка — не характеристики нашего провода

Для демонстрации различия зададим *условно* 1 км контактной линии, C=10 нФ/км, L=1 мГн/км, напряжение 25 кВ RMS и ток 800 А RMS при идеализированном синусоидальном режиме. Тогда усреднённые запасы:

- `E_C_avg = 0.5 × C × U_rms² = 3.125 Дж`;
- `E_L_avg = 0.5 × L × I_rms² = 320 Дж`;
- `E_fields_avg ≈ 323.125 Дж` на выбранном примере.

На отдельных фазах переменного тока мгновенные энергии меняются; мгновенный максимум любой компоненты может быть вдвое больше её среднего. Числа C и L **не измерялись в моде и не являются параметрами реальной конкретной железной дороги**. Величина 333 334 Дж в скрытом EEI примерно **в 1032 раза больше** данной иллюстративной средней полевой энергии 1 км: это следствие программного межтикового буфера, а не физической ёмкости 25-кВ контактного провода. Дуга, питаемая от включённого источника, может рассеивать дополнительно энергию и не ограничена только этой оценкой поля.

## 3. Утверждаемый контракт игровой механики

| Событие | Что может исчезнуть | Что нельзя автоматически списывать |
|---|---|---|
| Удаление тяговой подстанции | Измеренный запас скрытых EEI **только удаляемой подстанции** | Энергия оставшейся подстанции, других сетей, внешних аккумуляторов |
| Удаление/обрыв контактного провода, опоры, рельса | В будущем — энергия **явно смоделированного поля повреждённого участка**, и/или реально измеренной дуги, если она реализована | Весь EEI-буфер 333 кДж по факту разрыва без источника/расхода |
| Штатное выключение без уничтожения | Накопленные `E_line_field` только при смоделированном разрядном пути | Аккумуляторы, энергию независимых сетей |
| Объединение обычных заводских сетей | В будущем — рассчитанная и смоделированная переходная потеря из `L/C`, если есть модель электрических потенциалов | Произвольные 0.5 МДж технических портов моста |
| Разделение заводских сетей | Как для разрыва: только реально списанная полевая/защитная энергия | Заряд других подстанций и батарей |
| Реконфигурация маршрута без физического повреждения | Ничего сверх учтённых допустимых потерь в конкретных устройствах | Невидимое уничтожение буферов транспортного алгоритма |

**Правило по умолчанию для текущей 0.1.62:** поскольку линия не имеет отдельного `E_line_field`, *не выдаём* право списывать 1,5 МДж из EEI только на основании физической возможности дуги. Результат EM065 остаётся **FAIL по необъяснённому расходу**, хотя более старое общее требование «никаких потерь» заменяется событийному бухгалтерскому учёту. Это различие является основным выводом.

## 4. Проверенные данные EM065, повторная классификация

Испытан официальный Factorio Headless 2.1.24 (build 87808), исходный ZIP 0.1.62 SHA256 `a869c7fb5b76aa49ae38f50af8f1c74b9e8dcd9254e4e354b127e3698d966a07` и закрытый источник **700 МДж, 0 Вт новой генерации**.

| Стенд | Изменение реально существовавшего запаса, Дж | Законно списывается с удаляемой B, Дж | Осталось без объяснения, Дж |
|---|---:|---:|---:|
| Без аккумуляторов | 1 666 667 | 166 667 | **1 500 000** |
| С восемью штатными аккумуляторами | 1 724 409 | 186 667 | **1 537 742** |

На одиночных этапах старый игровой код через `stop`, `detach`, `M.rebuild` вызывает удаление скрытых EEI, включая имеющие `energy>0`; подтверждённый в EM065 дефицит совпадает по времени с разрывами и перестройками. Однако в настоящих данных ещё нужно отделить конкретную уничтоженную энергию портов от энергии, штатно переданной движком **в момент тика**, поскольку скриптовый и движковый порядок обновления не одно и то же.

Аккумуляторы: 8/8 прежних `unit_number` сохранились, поток заряда/разряда каждой четвёрки в пределах native API; их остатки могут **штатно меняться** при работающей сети. Запрещено обнулять/подменять батареи ради учёта «дуги».

Тест `tests/switching_dissipation_contract_066.py` читает **те же** JSON-показатели EM065, признаёт только измеренный запас удаляемой B, не принимает гипотетические джоули поля вместо физически не существующего в игре запаса, выводит все события и при флаге `--strict` **ожидаемо возвращает код 1**. Это проверка корректности решения, **не исправление мода**.

## 5. Что требуется изменить в runtime после согласования реализации

**Предлагаемый технический подход:**

1. Перед каждым уничтожением скрытых EEI собирать `energy` по паре портов, идентификатору подстанции, её status и причине (`substation_destroyed`, `rail_removed`, `mast_removed`, `factory_merge`, `factory_split`, `mode_change`, `topology_rebuild`). Не списывать энергию от соседей в событие удаления B.
2. При физическом уничтожении подстанции: прекращать новый вход/выход, уничтожать **только** её собственные EEI с полной записью `dissipated_j`, не трогая старые аккумуляторы/другие станции. Запись состояния и очистка — один жизненный цикл, не двойной счёт.
3. При обновлении графа без уничтожения подстанции: по возможности сохранять её существующие совместимые EEI; если сети изменили native IDs, **прекращать новую передачу**, корректно завершать временную операцию либо помечать энергию как неподтверждённую до безопасной обработки. Не переносить её через отключённый участок, не зачислять в заводской EEI вручную и не оставлять бесконечно активный порт. Отдельная конечная стратегия обработки зависшего в транзите запаса требует нативного теста.
4. Ввести отдельный источник рассеяния *линейной* энергии только **после** явного создания и учёта `E_line_field` (или защитного `E_arc_dissipated` с точным энергосписанием). Не притворяться, что существующий 333-кДж EEI = поле провода.
5. Телеметрия: `event_id, tick, entity_id, event_kind, domain, energy_before_j, energy_after_j, actually_dissipated_j, recipient_network_id`. При отсутствии данных — `unexplained`, а не «разрешённая дуга».
6. Новый критерий выпуска: ноль необъяснимого создания энергии, ноль необъяснимых исчезновений, отсутствие передачи через разорванный маршрут, штатные аккумуляторы целы, правильный заводской приоритет, бесконечных EEI-портов нет, повторный save/load и сетевые нагрузки 32/48 станций PASS.

**Важный компромисс:** «скрытая энергия не исчезает при любом разъединении» нельзя обеспечивать искусственным перераспределением по **неподключённым** электрическим сетям. Если по выбранному геймдизайну переходная энергия действительно рассеивается, разрешать это нужно явным правилом, конкретным источником и измеренным пределом. Иначе теряется смысл строгого закрытого энергобаланса.

## 6. Статус и следующий шаг

- EM066 = проверенный физический контракт + автоматический чистый Python-классификатор, **без игровых изменений**.
- EM065 показывает 1.5 МДж (и 1.537742 МДж с батареями) необъяснённого исчезновения; старое требование «ноль любой потери» заменяется `loss_accounted_by_event`. **Релиз по-прежнему заблокирован**.
- Следующая игровая реализация: в отдельной дочерней ветке добавить телеметрию владельцев буфера и безопасную обработку `stop/detach/M.rebuild`, затем повторить оба закрытых стенда 065, 064 save/load, 32/48 станций, cold-start, реверс и brownout. Только после нативного PASS решать вопрос выпуска версии с новым номером.
- PR и Updater 0.1.61 не сливать/не изменять без решения владельца. Нет доказательства совместимости Bob's Power в данных нативных стендах.
