# EM072-A5-B10R — предварительный контракт перед тестом

**2026-11-22. Исследование отдельно от main.** Целевая версия — Factorio 2.1.24 build87808 Linux Headless. Используется Base-only **отдельный** тест-мод. Актуальная архитектура — `docs/architecture/EM072_TRAIN_ENERGY_BUS.md` (PR #63), план — `docs/plans/DISTRIBUTED_TRACTION_072.md`. Исторический PR #62 с батареей моторного вагона признан NONCOMPLIANT и не используется как источник допустимой модели.

## Проверяемая гипотеза

Физически сцепленный состав из **2 locomotive + motor cargo wagon + motor fluid wagon** может иметь одну **временную логическую шину** для совместного расхода *только батарей локомотивов*, владеющих собственным зарядом через постоянный `LuaEntity.unit_number`. Моторные вагоны не имеют энергозапаса, 25-кВ токосъёма и самостоятельных источников энергии. `LuaTrain.id` меняется при реальной сцепке и расцепке, но не должен менять сохранённые J. После расцепки ранее состоявший в поезде электровоз может израсходовать свой защищённый одиночный резерв на реальное нативное движение.

## Стенд и отрицательный контроль

- Две настоящие native locomotive-clone `em-b10r-battery-loco` с отдельными сохранёнными скриптовыми энергозапасами 600 кДж и резервами по 200 кДж; предельная отдача 1 МВт **строго для данного стенда**. В составе две подлинные машины `em-b10r-motor-cargo-wagon` (cargo) и `em-b10r-motor-fluid-wagon` (fluid), **без** батарей и FuelEnergySource, без выдачи тяговых J.
- Третий, независимо созданный одиночный locomotive имеет 300 кДж, резерв 150 кДж, до 300 кВт. Общая сохранённая энергия в четырёх физических движимых типах **1,5 МДж**: только три электровоза; оба вагона — **строго 0 Дж**.
- Реальные события `on_train_created`, `LuaTrain.carriages` (состав), disconnect/connect, сравнение сохранённых J до/после. При отделении вагонной пары (0 локомотивов) любой запрос шины должен выдавать 0 Дж.
- Подставить в `states` фиктивный аккумулятор для каждого вагона и потребовать ошибку `bus.snapshot()` — fail-closed; после удаления поддельной записи настоящий энергобаланс неизменен.
- Состав расходует 800 кДж от двух локомотивов, остаётся A 200 кДж + B 200 кДж, оба не передаются другим участникам. Отдельный третий locomotive расходует 300 кДж включая собственный резерв; затем **настоящая повторная расцепка** и ранее присоединённый B расходует все оставшиеся 200 кДж на собственное движение. A остаётся с 200 кДж. Отданные нативным двигателям/потраченные J 800000+300000+200000=1300000; замкнутый остаток +200000=1500000.
- **Нельзя:** `LuaTrain.speed = ...`, прямое начисление J в батарею вагона, EM070/25-кВ-клейм без EM070 (здесь Base-only), обещание реального добавления 500 кВт в Factorio. Паспортная формула 2+2+0.5+0.5=5 МВт регистрируется как *модель*, но не подтверждённая дополнительная тяга.
- Настоящий Linux Factorio headless: 241 тиков benchmark; реальный сервер disk SAVE t100, затем независимый `--test-save` 141 тиков. Все метрики совпадают с полным бенчмарком. Запускать в полностью одноразовой директории, без пользовательских сохранений.

## Критерии отказа

Сохранённый заряд по физической unit_number изменился при одной сцепке/расцепке; любой моторный вагон хранит хоть 1 Дж или пытается передать батарейные J; отцепившийся локомотив не может двигаться на собственном резерве; потраченные native burner J превышают списанные реальные finite batteries; общая энергия не замыкается; SAVE→LOAD меняет метрики; не было подлинного `on_train_created` или скрипт устанавливает `train.speed`.

**За рамками:** 2+ действующих EM070 на одной шине, настоящие 500 кВт моторного вагона, его рекуперация, заводские/коридорные источники, фактическая зарядка, UI, Multiplayer/Undo/Blueprint/Mining/60UPS. Эти gates отдельные.
