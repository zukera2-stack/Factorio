# EM072-C2 — можно ли изменять max_power электровоза при сцепке без топлива?

**22.11.2026. Фактический результат: НЕТ, прямой Runtime API Factorio 2.1.24 не поддерживает изменение `max_power` живого локомотива или его прототипа.** Это ответ на предложенный автором вариант А: моторные грузовые и жидкостные вагоны остаются настоящими вагонами без аккумуляторов, суммарная мощность рассчитывается как 2MW × locomotives + 500kW × motor wagons. Гипотеза «при старте состава просто установить у электровоза `max_power=3MW`» не проходит.

## Источник и механизм

Официальный `LocomotivePrototype.max_power` — поле **data stage**, определяемое перед загрузкой игрового мира. В `LuaEntity` и `LuaEntityPrototype` runtime этого изменяемого свойства нет. `LuaEntity.prototype` доступно для чтения, но не записи. См. официальные URL:

- https://lua-api.factorio.com/latest/prototypes/LocomotivePrototype.html
- https://lua-api.factorio.com/latest/classes/LuaEntity.html
- https://lua-api.factorio.com/latest/classes/LuaEntityPrototype.html
- https://lua-api.factorio.com/latest/auxiliary/data-lifecycle.html

## Настоящий тест Factorio

**Движок:** Factorio 2.1.24 build 87808 Linux Headless, Base-only. **Не** устанавливался и **не** тестировался игровой ElectrifiedMainline 0.1.62. Отдельный лабораторный мод `em-power-api-probe 0.0.1`, полный код в `tests/em072-c2-power-api-probe/`, точный stdout в пользовательской Library (репозиторий хранит воспроизводимый исходник; логи могут оставаться только в Library) и Library `/Factorio/Network-062/EM072C2-dynamic-maxpower-20261122/`.

### Нативные API-отказы

Существующий native locomotive `em-power-2mw` был реально создан на native straight-rails (не макет), а записи выполнялись под `pcall`:

| Попытка | Фактическое сообщение движка |
| --- | --- |
| `loco.max_power` прочитать | `LuaEntity doesn't contain key max_power.` |
| `loco.max_power=3000000` | `LuaEntity doesn't contain key max_power.` |
| `loco.prototype.max_power=3000000` | `No modifications of LuaEntityPrototype are currently possible.` |
| `prototypes.entity["em-power-2mw"].max_power=3000000` | `No modifications of LuaEntityPrototype are currently possible.` |
| `loco.prototype=prototypes.entity["em-power-3mw"]` | `LuaEntity::prototype is read only.` |

**Поддерживается только до запуска мира:** `data.lua` создаёт два *разных* нативных прототипа `em-power-2mw` и `em-power-3mw` с `max_power = "2MW"` и `"3MW"` соответственно. Оба использовали именно `energy_source={type="void"}` **исключительно ради изоляции и сравнения физики**, а не как действительное электрическое питание. Созданы два реальных локомотива на независимых рельсовых линиях, в каждом native driver и acceleration через `riding_state`, без записи `LuaTrain.speed`.

| Тик | 2MW, native y (тайлов от начальной позиции) | 3MW, native y |
| --- | ---: | ---: |
| 60 | 26.203125 | 39.234375 |
| 120 | 93.785156 | 111.234375 |
| 180 | 165.785156 | 183.234375 |

На t120 оба достигают ограничителя 1.2 tiles/tick; разница в пройденном пути к t180 составляет **17.449219 тайла**, обусловлена более быстрым ранним разгоном. **Отдельные моторные вагоны в C2 не участвовали**; это исключительно проверка свойства прототипа и API. Ни 500kW вагонной тяги, ни законного источника электрических J опыт не подтверждает.

## Решение по исследовательской ветке

1. Автор выбрал концепцию **А**: сохраняем настоящий `cargo-wagon`/`fluid-wagon`, хотим честную дополнительную мощность состава; запрет на вагонные батареи сохраняется, а топливные множители и прямую запись скорости автор просил не использовать.
2. **Нельзя** выполнять `loco.max_power = 2MW + 500kW*N_wagon` при сцепке, смене `train.id` или пуске. Это технически отсутствующая операция API и не может быть исправлено Lua-алгоритмом.
3. Заранее созданные 2/2.5/3/...MW прототипы двигателя **физически работают**, но переключение уже установленного локомотива потребовало бы **замены реальной сущности**. Это может уничтожить `unit_number`, связи сцепки, настройки, сохранение батареи, инвентарь и расписание; безопасная миграция и native A/B engine acceptance **не проверены**. НЕ проводить замену в production без отдельного решения.
4. `VoidEnergySource` с 3MW делает ускорение бесплатным. Нужен действительный конечный энергетический источник и оплата J (в игровом UI это **не обязательно игровое топливо**, но движковый источник/передача конечной энергии всё равно обязателен). Честный чисто-безтопливный 3MW конвейерный привод с динамически изменяемым `max_power` пока **не найден**.
5. Следующий независимый технический тест без дополнительных концептуальных решений: сделать исследовательские варианты **фиксированных** прототипов с `max_power` разного номинала и проверить, можно ли сохранить реальную train-идентичность и состояние при замене **только на остановке в отдельном мире**, не подменять результат симуляцией `speed`. При провале оставлять архитектурный блокер владельцу; замена не утверждена.

**Scope:** documentation and experimental code only; main remains 0.1.62 void, no release/tag/installer and no automatic 500kW wagons.
