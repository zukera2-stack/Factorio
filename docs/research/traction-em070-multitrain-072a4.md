## 2. Как устроен исследовательский контроллер

**Заявка:** зарегистрированный `unit_number` сопоставляется с настоящим `LuaTrain.id`; одинаковое `unit_number` учитывается единожды. Если у одного состава две тяговые единицы, логический запрос суммируется один раз по train ID, а не умножается на число станций. Для каждого подтверждённого line-network в `direct[network_key].demand` добавляется **одна общая** сумма заявок до штатного `dispatch.plan`.

**Физический бюджет:** выдаётся не больше `min(r.output.energy, 20MW/60)` с каждой реально активной native EM070 output EEI. Для каждого train ID применяется детерминированное `max-min fair share`; реальный debit output EEI выполняется в том же тике, что credit native `LuaBurner`. Запросы без проверенного физического пути запрещаются.

**Кэш:** один ограниченный обход `get_connected_rail` от **физически найденного HSR-рельса возле feeder mast**, совпадающего с его записанным `rail_id`. Используется `unit_number` рельсов, `surface`, `force`, `technical_046.components`, `electric_network_id` и `tech.sync_generation`. Кэш сбрасывается при вызове уже существующего `power_019.on_rail_changed` (в исследовательской копии добавлен hook) и при поколении технической сети. **К тикy 200:** всего **2 построения кэша** для двух станций, сотни повторных чтений без BFS. **На конец теста:** **6 построений**, **2510 попаданий в кэш**. Начальная постройка ~322 рельсов вызвала многочисленные инвалидации; это **не** 322 полных обхода. При слишком длинной сети (предел 4096 visited rails) алгоритм **fail-closed**.

**Важный урок из нативной проверки:** `game.get_entity_by_unit_number(root_rail_id)` возвращал `nil` для тестового рельса. Поэтому кэш не строится с предположения, что рельс всегда доступен через общий lookup; он привязывает `power.nodes[mast_id].rail_id` к **реально найденной сущности рельса возле мачты**. Это устранило ложный отказ при кэшировании.

**Избежали ошибочного теста:** физический разрыв между двумя станциями не должен обесточивать путь, который остаётся связан со второй станцией. Принят только разрыв за **обеими** мачтами, после чего оба локомотива действительно теряют связь. При выключении одной станции с сохранением связности вторая правильно продолжает питание.

## 3. Чётко отделённый алгоритмический тест ограничения 20 МВт

Чисто детерминированный Lua-алгоритм рассчитан на **12 независимых поездов × 2 МВт** при единственной доступной станции **20 МВт**. Каждому выделено **1,666666… МВт**, суммарно не более 20 МВт, независимо от порядка записей. В другом примере **2 поезда × 2 МВт, 3 МВт доступно**: каждому **1,5 МВт**. Тестируется также группировка **двух локомотивов одного native train ID** в одну заявку 4 МВт и исключение повторной регистрации одинакового unit ID.

**Важно:** настоящие *12 движущихся поездов при перегрузке* **НЕ** тестировались. Не называть unit-test измерением native factory brownout или доказательством общей способности сети. В нативном опыте 2×2 МВт находятся внутри общей мощности двух подстанций.

## 5. Оставшиеся риски и границы EM072-A4

Это **узкий успешно доказанный прототип**, а не готовая реализация в основной игре. Нельзя сливать тестовый hook в `main`:
- Действительный `em-electric-locomotive` всё ещё `energy_source={type="void"}`; тест использует отдельный burner clone и тестовый `character.riding_state`. Нет автоматического расчёта расхода по throttle/расписанию, нет полноценной миграции старых электровозов.
- В тестовой системе зарегистрированы вручную **только два локомотива**; native `on_train_created` при разбиении/слиянии поездов, несколько электровозов в одном составе, 12 движущихся поездов, физическая перегрузка и заводской brownout требуют отдельных тестов.
- Прототипный алгоритм разделения по поездам **ещё не доказывает справедливость при нехватке мощности на разных несвязных компонентах или при неравной достижимости нескольких станций**. Не переносить без переработки групп по физическому сетевому компоненту, контроля границ и fairness под дефицитом.
- В текущем native test всего две станции и сравнительно короткий путь. Продакшн UPS для тысячи километров, cache eviction, rail ghosts, elevated, Space Age, команды с многими силами и MP не измерены.
- Батарея локомотива, рекуперация и запрошенные владельцем **моторные cargo/fluid вагоны по 500 кВт**, которые не берут 25 кВ напрямую, **не внедрены**.

**Следующий шаг:** EM072-A5 — 12 движущихся поездов под ограничением реального источника 20 МВт, несколько независимых power-components, динамический `LuaTrain.id` split/merge и измерение UPS. Затем EM072-C — нативная проверка +500 кВт на моторный cargo/fluid при сохранении инвентарей, без записи `train.speed`. Оставить ветку/PR в статусе DRAFT, не выпускать ZIP как мод.
