# EM072-C — нативный опыт: нет независимых +500 кВт у cargo/fluid без механизма привода

**Дата:** 22.11.2026. **Результат:** три независимых реальных Factorio 2.1.24 Linux Headless Base-only состава по 241 тик, настоящий серверный SAVE t100 → независимый LOAD+141. **ДИАГНОСТИКА PASS, ТРЕБОВАНИЕ +500кВт МОТОРНОГО ВАГОНА НЕ ДОКАЗАНО / ТЕХНИЧЕСКИЙ БЛОКЕР.** Исследовательская ветка, не production. [Предпосылки и критерии](native-motor-wagon-traction-c-preflight.md), [точные замеры](native-motor-wagon-traction-c-result.json), [воспроизводимый запускатель](../../tests/run_native_motor_force_072c.py).

## Реальная схема движка

Нативные `locomotive` **2 МВт** и по два вагона `cargo-wagon`+`fluid-wagon` на каждой из трёх независимых прямых путей. У всех трёх одинаковая физическая масса всех частей, скорость начинается с 0, одинаковая физика и топливный запас **20 МДж** на локомотив. A — пассивные ванильные клоны; B — новые моторные cargo/fluid, но всё ещё физические типы wagon; C — тот же моторный состав, но item локомотива с `fuel_acceleration_multiplier=1.25` и тем же номиналом `max_power=2MW`. Во всех случаях **нет** батарей моторных вагонов, прямого энергоснабжения 25 кВ, `LuaTrain.speed`-записей, скрытого локомотива, дополнительно начисленных J.

## Что удалось доказать и что нет

- **GAME-TESTED:** native cargo/fluid с простой «моторной» маркировкой не создают тяговый вклад; единственный вариант с большими расстояниями повлиял на **локомотив**, но не увеличил нативный расход J и не моделировал отдельный электрический мотор-вагон. Все три finite LuaBurner имели корректное внутреннее nJ-состояние и не перезаполнялись бесплатно.
- **API-CONFIRMED (версия страницы 2.1.24 для cargo/fluid):** у `CargoWagonPrototype`/`FluidWagonPrototype` нет поля locomotive `max_power`; штатный двигатель не предоставляет независимого wagon wheel propulsion просто по имени.
- **NOT PROVEN:** что движок принципиально не позволяет никакой другой безопасной реализации, или что множитель нельзя использовать как строго оплачиваемый прокси. Прокси был бы новой моделью, требующей отдельного разрешения автора и дополнительных тестов: нативное ускорение через локомотив, обоснованный **дополнительный** расход 500кВт на мотор-вагон, ограничение source/состояния, 0/1/4 вагона, приём/возврат энергии и проверка различия от free acceleration.
- **НЕ менять** производственные `ElectrifiedMainline/`, `max_power`, `LuaTrain.speed`, прототипы/заводскую подстанцию, **не утверждать готовую моторизацию**. Числа Base-only не указывают характеристики реального HSR.

## ВОПРОС АВТОРУ — архитектурная развилка

**А. Разрешить оплачиваемую аппроксимацию.** Вагон остаётся native cargo/fluid с полным грузовым функционалом и без батареи. Контроллер состава увеличивает ускорение locomotive через разрешённое игровое свойство, **только одновременно со строго измеренным дополнительным дебетом по 500 кВт/вагон из общей поездной энергосети** и ограничением по току и заряду. Нельзя утверждать, что колёса нативно имеют собственный двигатель; физическое движение состава остаётся движку Factorio, скорость напрямую не записываем. Требуются дополнительные 0/1/4 и энергетические A/B native тесты прежде чем внедрять.

**Б. Требовать независимый мотор самих cargo/fluid вагонов без модели через локомотив.** Пока API Factorio 2.1.24 не предоставляет такого поля, внедрение отложить, не разрушая существующую грузовую и жидкостную механику. Искать более глубокий API/другой способ и предъявить новый native тест, затем решение владельца.

Оба варианта сохраняют утверждённые: аккумуляторы **только у электровозов**, электросеть по составу, рекуперация в шину при реальном торможении, AUTO EM070 policy Б. **ВЫБОР НЕ СДЕЛАН**, никакие игровые изменения не предприняты.
