# EM072-A2 — передача реальных джоулей EM070 в штатный LuaBurner

**Дата:** 21.11.2026. **Статус:** GAME-TESTED PASS на изолированном нативном стенде, **не интегрировано** в игровой мод. Ветка `experiment/native-em070-burner-debit-072a2` основана на предыдущем EM072-A. Исходная версия мода 0.1.62 остаётся с `VoidEnergySource`. Движок **Factorio 2.1.24 build 87808 Linux headless x64**, Base + ElectrifiedMainline, DLC отключены. Никакого релиза, патчера или изменений `main`.

## 1. Реальный механизм

Пять настоящих ванильных аккумуляторов по 5 МДж (начальный запас **25 МДж**) питают заводскую сеть №4. Нативная EM070-подстанция в **ручном режиме import** передаёт реальные J через свои `electric-energy-interface` input/output buffers в коридорную сеть №5. Временная тестовая функция внутри *одноразовой копии* control.lua проверяет состояние станции и родной `line_port`, читает её реально заряженный `r.output.energy`, выдаёт не более **2 МВт / 60 = 33 333,33 Дж/тик** в нативный `LuaBurner.remaining_burning_fuel` и **ровно на величину выданного** уменьшает исходный `r.output.energy`. У каждой операции один источник и один приёмник.

Состав движется только родным `BurnerEnergySource` с настоящим `character.riding_state.accelerating`, **никакой записи в `LuaTrain.speed`**. Прототип `em072-grid-burner-loco` существует лишь в test fixture и клонирует наш 2MW локомотив; штатный 0.1.62 остаётся `void`.

**Точное исходное EM070 содержимое НЕ менялось:** Git blobs `power_bridge_058.lua=4a4084e5cf71d57cc057aa15bc524ac68ff6268b`, `technical_network_046.lua=e8b1bad35fb60d22bdb91d2dd1c4c5055c58e172`, `bridge_dispatch_059.lua=4f4399d6277c27ec65b73d45fd1bf82f89d4bfe2`, `scripts/control.lua=3546d3b7c983856c367279d5dac21fe1c8b07f95`. Они идентичны содержимому `main`. Тестовый `remote.add_interface` добавляется **только к скопированному в scratch каталогу** корневому `ElectrifiedMainline/control.lua`.

## 2. Нативные результаты

Испытание Factorio 2.1.24: **380 тиков** по настоящим рельсам. Реальная линия с тремя мачтами и подстанцией; второй локомотив расположен на параллельных обычных, физически не электрифицированных рельсах.

| Измерение | Результат |
| --- | ---: |
| Стартовый резерв пяти штатных аккумуляторов | 25 000 000 Дж |
| Выдано из настоящего буфера EM070 в LuaBurner к тику 240 | **5 116 668 Дж** |
| Потрачено штатным двигателем к тику 240 | **5 091 668 Дж** |
| Остаток топлива в двигателе на тике 240 | **25 000 Дж** |
| Необъяснённый энергетический остаток | **~0 Дж** |
| Второй локомотив на обычных рельсах | **0 Дж** (отрицательный контроль PASS) |
| Переключение настоящей станции EM070 в OFF на тике 270 | **0 новых Дж после OFF** к тику 330; баланс ~0 Дж, PASS |

Инвариант измерений: `sum(accumulator.energy + real EM070 input.energy + real EM070 output.energy + burner.remaining_burning_fuel + cumulative_native_burned_J) = 25 000 000 J`. Необъяснённый остаток в нативном логе `-0.000`, включая после отключения (`-0.000000`).

**Настоящий SAVE→LOAD с диска:** headless server сохранил карту на тике **151** при идущей тяге; отдельный процесс Factorio загрузил checkpoint и продолжил **210 тиков**, проверив те же три PASS, включая OFF. Размер checkpoint **534714 bytes**. SHA256 обычного нативного benchmark лога: `f15fb2d63f38646558f83c568d003711c63945ad76e9d7d90f630c44fbb6601a`; лога после загрузки: `2caf429ae02bd0e55b6e15f9279e588168d0c39c87ccdbca29470dd4e9d6e74f`.

## 3. Неудачные проверки и ограничения

- Первоначальная попытка расположить дополнительный энергоинтерфейс на видимой мачте **не дала доступа к правильной сети**: возле подстанции он подключался к заводской сети, на удалённой мачте `electric_network_id=nil`. Скрытые `technical_network_046` провода защищены аудитом собственности. Поэтому в успешном тесте не создавали дополнительного физического EEI потребителя или провода — работали только с существующим родным EEI buffer EM070.
- **AUTO-питание НЕ доказано**: станцию в стенде принудительно переводили в `import`. Диспетчер EM070 без внешней заявки состава может оставаться `auto-idle-no-connected-peer` даже при реальной потенциальной тяговой потребности. Нужен безопасный native demand.
- **Рельсовая связность НЕ доказана полностью**: тест отвергает локомотив на обычном рельсе, но наличие рельса с именем HSR на той же карте ещё **не означает соединения именно с этой питающей станцией**. Другой несоединённый HSR участок требует отдельного отрицательного теста через проверенную RailEnd/technical component topology.
- Моторные грузовые вагоны и цистерны **+500 кВт на вагон** пока только планируются; тяга, отдача в локомотив, аккумулятор EM073 и рекуперация EM074 отсутствуют.
- Текущий native test не проверял одновременно несколько локомотивов, поездной автопилот, разрыв настоящего HSR/feeder, конкурирующие электрические нагрузки, мультиплеер или произвольные старые сохранения.
- Обычное зачисление J без **реального встречного списания** из существующего EEI по-прежнему **запрещено**.
