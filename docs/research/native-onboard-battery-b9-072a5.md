# EM072-A5-B9 — AUTO политика Б и конечная бортовая батарея локомотива: отдельный native-тест

**Дата:** 2026-11-22. **Источник решения:** автор явно выбрал Б: «AUTO может поддерживать завод даже при дефиците тяговой мощности». **Тест:** настоящий Factorio 2.1.24 build 87808 Linux headless, Base; игровой мод ElectrifiedMainline 0.1.62 из официального оригинального EM071/EM070 CI ZIP SHA256 `91aef47ca13a0009e46ab92c9ad5735e0af30c6acc16bab1cf0507a8855a2575`, CI run 44925677432. Испытания производились **только в одноразовых копиях**, код `ElectrifiedMainline/` в GitHub и `main` не изменён.

## Утверждённая архитектурная политика

**EM070.AUTO_B_APPROVED:** при недостатке мощности на фабричной стороне EM070 **может перейти на экспорт энергии из контактной магистрали в фабрику даже при одновременном дефиците тяги**. Приоритет «поезда всегда важнее фабрики» **не вводить**. Прежний B8 native-прогон AUTO уже демонстрирует это поведение. Возможность ручного принудительного `Import` не удаляется; не изменять смысл других режимов без решения автора.

Отдельная, всё ещё **не принятая** развилка: фабрика-первая/аккумуляторы аванпоста-первые при зарядке и расходовании **стационарных** 120 МДж на контактной линии. Она не равна политике бортовой батареи.

## Что именно проверяется

На общей **одной физической HSR** две реальные EM070 с независимыми заводскими native electric сети. На обоих заводах по 84 конечных обычных accumulator: всего 840 МДж. **16 реальных, независимых, действительно движущихся native burner-locomotive** с собственными драйверами и без присваивания `LuaTrain.speed`. Тестовая нагрузка тяги: 2 МВт каждый = 32 МВт. Контактная сеть питается только через реальные нативные EEI EM070; реальный конечный native input meter списывается по фактическим `meter.energy`. На заводе B t260 включается фактический native EEI потребитель 30 МВт при потолке нативной аккумуляторной отдачи 25,2 МВт; на 217 тиках фабрика B недополучает заявленную мощность. В ходе дефицита **EM070 B остаётся в AUTO и экспортирует в завод B**.

**Бортовая батарея — отдельный конечный программный запас Дж, привязанный к отдельному индексу настоящей сущности локомотива в парных массивах `storage.b8.locos[i]` / `storage.b8.battery[i]`**, а не физический `accumulator` с дополнительным нативным электрическим разъёмом. Энергия батареи строго уменьшается перед зачислением в **реальный `LuaBurner.remaining_burning_fuel`**; нативный двигатель расходует её обычным образом. Этот тест подтверждает алгоритм и закон сохранения энергии, но **НЕ** доказывает существование готовой производственной бортовой батареи и не подтверждает recharge/Undo/Blueprint.

Исследовательские значения (**не фиксированы автором как игровые характеристики**): 2 МДж начального заряда/локомотив, максимум 1 МВт отдачи с батареи на локомотив. У 16 поездов всего 32 МДж. Квота бортовой компенсации на каждом тике `b_i=min(max(0,(2MW/60)-g_i),1MW/60, B_i)`, где `g_i` — реальные native J из контактного EEI; затем `B_i:=B_i-b_i`, `burner_i:=burner_i+g_i+b_i`. Когда в контактной сети достаточно энергии, запас не расходуется. **Никакого добавления/перезаписи native электрических аккумуляторов в тиках нет**. При полном исчерпании бортового запаса значение `b_i=0`; уже зачисленные нативным топливным буферам J могут оставаться до действительного сгорания.

### Проверка физики и отсутствия бесплатной энергии

- **Идентичное native grid** в двух отдельных опытах: 148,492753623 МДж.
- Разница в зачислении двигателям **ровно +32,000000000 МДж**, строго равная уменьшению 16 независимых батарей на 32 МДж.
- Заводской экспорт EM070 B в обоих сценариях **10,217391304 МДж**. Выбор Б сохранён.
- Native global finite ledger включает 168 factory accumulators, четыре EEI двух мостов, реальный meter, factory B load, **бортовые остатки** и реальные burner (не сгоревшее + сгоревшее); абсолютная невязка <0,01 Дж в обоих сценариях.
- Сравнение выполнено строгим `tests/run_native_battery_matrix_072a5b9.py`, который запускает обе версии, требует живой нативный Factorio, проверяет исходный ZIP+5 Git blob, создаёт реальный SAVE и сверяет все цифры с независимым LOAD.
