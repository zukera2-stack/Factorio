# 0.1.62: честное распределение между независимыми электросетями

**Дата:** 2026-11-21. **Статус:** новая исследовательская сборка, **не утверждена для патчера**.

## Проблема (настоящий игровой тест)

Подстанция мощностью 20 МВт соединена с одной общей контактной сетью. К ней подключены две независимые заводские сети, каждая с потребителем 20 МВт. Существующий `bridge_dispatch_059.lua` обходит назначения по ID и заполняет сначала одно направление. При непрерывной нагрузке вторая заводская сеть голодает. Это выявлено в прямом вызове реального `M.plan` на 0.1.61 (20/0 МВт), а затем подтверждено **официальным Factorio Headless 2.1.24 build 87808** на тестовом моде `em062-fairness-probe` с 0.1.61: за 240 игровых тиков потребитель B получил 78 666 667 Дж, потребитель C — 0 Дж; тест завершился с ожидаемой ошибкой `starvation detected`.

## Минимальное изменение

На основе **строго проверенной 0.1.61** (базовый коммит `c8a1feddddfb3f160eae5f63cd1b0231e2136ce3`) изменён только `ElectrifiedMainline/scripts/bridge_dispatch_059.lua`: источник теперь в каждом проходе находит доступных потребителей одного уровня приоритета и делит оставшуюся доступную энергию между ними равными квотами. После каждой выдачи пересчитывается путь: ограничения станции, изоляция сетей, граф без направленных циклов и последовательность приоритетов `gen→load`, `battery→load`, `gen→charge` **сохранены**. Ограничение одной станции 20 МВт не изменилось. Версия `ElectrifiedMainline/info.json` увеличена до 0.1.62. Арт и остальные 128 файлов игры не менялись.

Семантика: **равное распределение среди достижимых потребителей одинакового приоритета на один источник**, а не математическая гарантия глобальной max-min справедливости для всех возможных графов, местных нагрузок или аккумуляторов. При насыщении линии или исчезновении потребителя остаток перераспределяется по доступным путям.

## Ограничения и дальнейшая проверка

- Bob's Power использован ранее в пользовательской карте 0.1.61, но **0.1.62 не проверена в самом движке с настоящим модом Bob's Power**, только с обычными аккумуляторами и приоритетами.
- При большом количестве подстанций расходы на маршрутизацию могут вырасти: следует провести профилирование на длинной магистрали.
- По-прежнему не реализованы физическая тяга электрического локомотива, глобальная регулировка напряжения 25 кВ и нативный аккумуляторный шлюз без Lua.
- Данные `flow_last_tick` и физическую изоляцию сети определяет движок; Lua-распределитель использует только уже учтённые джоули. Не объявлять проверенным произвольный граф на многих поверхностях/силах без дополнительного сценария.
- Не обновлять `test/updater-approved` и не сливать в `main` до отдельного разрешения владельца. Пользователю **не нужно** снова скачивать патчер или вручную устанавливать 0.1.62.

## Измерение и воспроизведение

При наличии предоставленного владельцем Factorio Headless 2.1.24:

```sh
FACTORIO_BIN=/path/to/factorio/bin/x64/factorio bash tests/run_headless_062.sh
```

Без локального бинарника скрипт получает официальный headless из `factorio.com` при запуске в CI. Он упаковывает установочный ZIP штатным `scripts/package_mod.py`, создаёт отдельные временные карты и требует всех трёх игровых PASS-маркеров; при сбое печатает конец журнала.

**Не путать:** сборка game mod 0.1.62 в экспериментальной ветке — не обновление патчера 1.1, который продолжает читать утверждённую тестовую 0.1.61 из `test/updater-approved`.

## Blocking follow-up from long-line stress (2026-11-21)

See [full 0.1.62 stress and 0.1.61 performance-control report](25kv-long-mainline-stress-062.md). On actual Factorio 2.1.24, 32 factory grids (single or four generators) and mixed local factory loads passed native stress, isolation, fair reallocation, source outage and factory priority tests. The 48-grid / six-generator / 42-sink test confirmed fair initial distribution (240 ticks) but revealed an alarming **performance regression**: minimum measured update time 27.357ms in 0.1.62 against 3.121ms in 0.1.61 on the same benchmark; 60UPS budget is 16.667ms. Cold-start world-building affects the mean; the minimum update time is still above budget. **DO NOT PROMOTE 0.1.62 TO UPDATER** before profiling/optimizing planner complexity and repeating the native performance and functional tests. This is a scoped benchmark finding, not a universal prediction of player's FPS/UPS. Original 83 art files and approved updater branch unchanged.
