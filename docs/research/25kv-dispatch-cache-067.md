# EM067 — ускорение Lua-диспетчера электрической сети 25 кВ

**Дата:** 21.11.2026. **Статус:** экспериментальный код, без разрешения на выпуск. Родительская ветка: `experiment/switching-dissipation-policy-066`; ветка изменения: `experiment/dispatch-cache-067`. Версия внутри мода **0.1.62** сохранена только для честного сравнения, Updater 1.1 по-прежнему использует **0.1.61**, а стабильный `main` содержит **0.1.56**. Слияние запрещено до решения владельца.

## 1. Выявленный недостаток

Ванильная Factorio на C++ обрабатывает электрические сети, генерацию, потребление и накопители. Lua-мод **не** заменяет этот движок: `power_bridge_058.lua` читает доступные электрические сети, `bridge_devices_060.lua` выборочно сканирует физические накопители и EEI, а `bridge_dispatch_059.lua` строит направленный план передачи через изолированную техническую сеть подстанций. Управление реальными Дж производится через нативные `electric-energy-interface`.

Мод уже использует события для перестройки геометрии, контроль технической топологии каждые 60/600 тиков и обновление снимков устройств не чаще раза в 60 тиков при неизменном составе сетей. Переписывать эти подсистемы вслепую нельзя.

До EM067 **каждый игровой тик** планировщик строил заново пути и повторно выполнял поиск достижимости в ориентированном графе даже при полностью неизменном спросе и электрической сети. При 200 узлах отдельный Lua-тест требовал около 19–22 мс для каждого такого вызова; это **не** измерение всего тика Factorio.

## 2. Что изменено в коде

**Только** `ElectrifiedMainline/scripts/bridge_dispatch_059.lua`:

1. **Кэш завершённого плана:** до расчёта проверяется точное равенство каждого нормализованного `gen`, `load`, `battery`, `charge` для всех идентификаторов электросетей, лимита передачи и всех отсортированных рёбер (`id`, `a`, `b`). Только при полном равенстве возвращается копия прежнего плана. Любое изменение мгновенно приводит к обычному новому расчёту. Никаких округлений и порогов, скрывающих небольшие изменения нагрузки.
2. **Кэш достижимости только внутри одного расчёта:** ответы обхода `reachable(from,to)` используются повторно, пока не появилась новая направленная дуга. При появлении такой дуги кэш сбрасывается. Проверка цикла для частично создаваемого маршрута учитывает предварительные дуги и обходится без небезопасного повторного использования прежнего результата.
3. **Предотвращение порчи кэша:** сохраняется независимая таблица выходных потоков, а попадание в кэш также возвращает новую таблицу. Вызывающий модуль не может изменением `plan[edge.id]` исказить следующий расчёт.
4. **Временные Lua-объекты не сериализуются:** кэш — локальное состояние модуля, содержит исключительно числовые данные, автоматически сбрасывается при перезагрузке скриптов и не хранит `LuaEntity`, `LuaElectricNetwork` или другие объекты движка.

Не менялись очередность приоритетов (генерация→потребление, аккумуляторы→потребление, генерация→заряд), лимит **20 МВт на подстанцию**, направленные ограничения, запрет циклов, исходная механика заряд/разряд, потери и правило демонтажа. Это **не** попытка исправить EM065/066 потерю EEI при разрушении.

## 3. Дифференциальная проверка с исходным алгоритмом

`tests/reference_bridge_dispatch_062.lua` — оригинальный, неизменённый код проверенной оптимизированной 0.1.62; `tests/bridge_dispatch_cache_067.lua` загружает обе реализации и сравнивает **каждый числовой поток**, а не только суммарную выработку.

**1675 вызовов PASS** при сидe `20261121`: случайные звёзды, линейные графы, случайные деревья и графы с циклами, размеры 2–16, отдельно 48/100/200 узлов, перестановки рёбер, изменения числовой мощности, повторный запрос, изменение ребра и повреждение ранее возвращённой вызывающему таблицы. Никаких несовпадений по потокам при допуске `1e-8` Дж в тесте. Старые регрессии `bridge_dispatch_059`, `bridge_dispatch_efficiency_062` остаются в CI.

## 4. Lua-микробенчмарк (не UPS)

Разовый замер на доступном Linux Lua 5.3 (`luahbtex --luaonly`, не игровой движок), `tests/benchmark_dispatch_067.lua`. Воспроизводить несколько раз и сравнивать медиану; цифры не являются гарантией на иной машине.

| Узлов | Постоянные входы: исходный → EM067, мс/вызов | Входы меняются *каждый вызов*: исходный → EM067, мс/вызов |
|---:|---:|---:|
| 10 | 0,106 → 0,010 | 0,114 → 0,116 |
| 48 | 1,243 → 0,056 | 1,405 → 1,039 |
| 100 | 4,975 → 0,401 | 5,133 → 3,792 |
| 200 | 17,684 → 1,428 | 19,006 → 14,190 |

Выигрыш при неизменных входах в основном достигается кэшированием готового плана. При изменениях каждое обновление всё ещё требует поиска маршрутов; при 200 подстанциях его цена остаётся существенной. Это аргумент для отдельного следующего этапа, а не повод отключать безопасность или пересчёт автоматически.

## 5. Настоящий Factorio 2.1.24: 48 подстанций

**Движок:** Factorio Headless 2.1.24 build 87808 Linux x86-64; **эталон:** точный опубликованный CI ZIP `0.1.62`, SHA256 `a869c7fb5b76aa49ae38f50af8f1c74b9e8dcd9254e4e354b127e3698d966a07`. **Локальный кандидат EM067:** ZIP SHA256 `2eac182f472de4a83805bb99dd87d428455ce5f69c0c9abd49917177bc3666a8`; после сборки GitHub его ZIP-байты могут отличаться из-за формата сжатия — для релиза потребуется **проверить и испытать точный CI ZIP**. По содержимому оба ZIP отличаются только названным одним Lua-файлом, все **83 PNG** и **остальные 129 игровых файлов** неизменны.

`tests/em067-48sub-probe/control.lua` проверяет 48 изолированных заводских сетей, 6 × 20 МВт источников, 42 одинаковых получателя и соединённую тяговую сеть. **960 тиков**: на тике 240 все 42 получают по **11 238 095 Дж**; после отключения половины потребителей оставшиеся 18 получают по **39 832 612 Дж** за 360 тиков; после отключения всех шести генераторов приращение ограничено переходными буферами. **И исходный, и оптимизированный ZIP PASS.**

Один полный native benchmark: общий средний тик **20,037 мс** для исходного архива и **20,235 мс** для окончательного кандидата (не улучшение в этом замере). Цифры включают создание карты в первом тике: пиковое обновление >6 с, так что по этому среднему нельзя заявлять прирост UPS. Отдельная предварительная версия EM067 показала 18,149 мс в другом прогоне; это подтверждает нестабильность таких единичных сравнений.

`--benchmark-verbose all` позволил отделить Lua и штатный расчёт электрических сетей. Для 300-тикового прогона **окончательного** кода среднее за тики 180–239:

| Показатель движка | Эталон 0.1.62 | EM067, финальный код |
|---|---:|---:|
| `scriptUpdate`, мс/тик | **8,033** | **4,696** |
| `electricNetworkUpdate`, мс/тик | **0,105** | **0,041** |
| `wholeUpdate`, мс/тик | **8,735** | **5,041** |

Это **отдельные последовательные прогоны**, без изоляции частоты CPU и влияния фоновой нагрузки, не строгий доказанный прирост на любой машине. Значение `scriptUpdate` включает **все Lua-части** нашей игры и временного тестового мода, а не только функцию `plan`. Для стабильного сравнения следует сделать несколько повторов на одинаковом сохранении, оценить медиану и p95; показания обновления штатных электросетей маленькие относительно Lua.

## 6. EM065: конечный источник и аккумуляторы

Финальный локальный ZIP EM067 прошёл обе настоящие игровые лаборатории EM065 (каждая 1350 тиков), с двумя независимыми серверными SAVE→LOAD (+200 тиков каждая):

| Сценарий | Проверки сетевой перестройки | Исторический дефицит EEI | Демонтаж по решению владельца | Создано энергии |
|---|---|---:|---:|---:|
| Источник 700 МДж, новая генерация 0 | 10/10 PASS | 1 666 667 Дж | 166 667 Дж разрешено | 0 Дж |
| То же с 8 внешними аккумуляторами | 10/10 PASS; 8/8 заряд/идентичность PASS | 1 724 409 Дж | 186 667 Дж разрешено | 0 Дж |

После загрузки каждого сохранения получатель получил дополнительно **13 333 333 Дж**. **Оставшиеся 1,5 / 1,538 МДж необъяснённого исчезновения — по-прежнему блокирующий дефект**; изменение распределителя его не исправляло и не скрывало.

## 7. Что не сделано и что делать дальше

- Не снижена частота расчёта безопасности или реальной передачи EEI: она всё ещё **каждый тик**. Переход на редкое обновление не разрешён, пока нет доказательства реакции на аварии и изменяющиеся нагрузки.
- Не изменены `bridge_devices_060.lua` и сканирование аккумуляторов раз в 60 тиков: оно может создавать периодические пики на огромных картах, но нельзя без проверки терять удалённые аккумуляторы или устройства других модов.
- Не подтверждены стабильные 60 UPS для 200 реально построенных подстанций, native Bob's Power, multiplayer и Undo/Redo. Эквивалентность на случайных графах не доказывает оптимальность max-min fairness в любых графах.
- Для дальнейшего ускорения нужны изолированные профили на 100/200 реальных подстанциях с изменяющейся нагрузкой, счётчик попаданий в кэш из самого движка и безопасный кэш **структурных маршрутов**, а не только результатов полной балансировки.
- **Перед выпуском исправить/формально классифицировать исчезновение EEI на разрывах и merge/split согласно EM066**. Разрешённое рассеяние энергии демонтируемой станции не должно затрагивать другую станцию или внешние аккумуляторы.

**Статус:** оптимизация и регрессионное тестирование готовы к PR, но релиз EM067 **не одобрен** и энергетический release gate пока **FAIL**. Не изменять `main` и `test/updater-approved`.
