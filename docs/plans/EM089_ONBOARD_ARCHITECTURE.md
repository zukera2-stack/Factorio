# EM089A — бортовые накопители: экспериментальная реализация
26.11.2026. Родитель EM088 `7c93659c523c460a494309883ac5a06190b1ceef`, 0.1.100. Утверждённая архитектура: [EM088–EM095](EM088_HYBRID_ARCHITECTURE.md). EM089A 0.1.101 — опытный функциональный этап, не owner-accepted, не релиз.

## Правила первой реализации
- Один конечный накопитель на физический `em-electric-locomotive` по unit_number. Нулевой начальный/миграционный заряд. `train.id` используется только для актуального расчёта состава; соединение, разделение, удаление не копируют состояние. Остаток удалённого носителя списывается как потери при 60-тиковом аудите. Предмет локомотива заряд не сохраняет.
- Встроенная логическая ёмкость, не новый физический полюс/сеть. Опытные startup параметры 60 МДж, 2000 кВт заряд, 4000 кВт разряд на каждый электровоз. Отдельный 2 МДж native burner reserve неизменен. Моторные вагоны 500 кВт через существующие helpers; на вагонах нет батарей/токосъёмников. КПД перевода для проверки баланса 1, реальный игровой КПД ещё не утверждён.
- Runtime-global `em089-experimental-onboard-storage` по умолчанию false (опытный режим, сохранение прежней механики). Выключение замораживает запас; не уничтожает его. Три startup настройки параметров. Уменьшение ёмкости списывает избыток в учтённые потери. Проверка изменения настроек в действующей игре и Windows GUI остаётся отдельной задачей.
- Сначала существующая native grid-to-burner оплата; затем `train_energy_088.transfer_store_to_burner` для оставшегося дефицита. Лимит движка/буфера и общий расход каждого накопителя ограничены. Детерминированный max-min между запросами одного состава, доноры отсортированы по unit_number; источники проверены по текущему train/force/surface. Не создаётся второй бесплатный источник или ручная запись скорости.
- Заряд первой версии консервативный: только стоянка, нет ожидающей тяги на данном составе/группе донора, нет разряда в том же составе на том же тике; настоящий контакт и активный auto-import мост. 059 отдаёт дополнительную карту распределённой генерации для tier charge после обслуживания load, включая приоритет battery->load. Эта карта не J, а ограничение запроса; 058 передаёт ограничение только в текущую синхронную фазу, 065 реально дебетует уже оплаченный native sink в режиме tertiary_input. При отклонённом запланированном мосте заряд на этом тике консервативно запрещается. В режиме manual-import заряд первого прототипа не разрешён. При остановке режима заряд/тяга не переводят неподтверждённые J; оставшийся native buffer учитывается отдельно. Сетевой поток запаздывает на тик; текущий план не доказывает физический источник каждого J в произвольной смешанной сети. Полный приоритет и переменные нагрузки требуют дальнейшей QA.
- Сохраняются прежние cumulative grid-paid counters (только grid-to-burner), новый журнал `em089_onboard_storage.snapshot` и `[EM089 STORAGE]`: charged = stored + discharged + lost. В закрытом стенде источник+нагрузка+native buffers+grid-paid+stored+discharged+lost = начальный бюджет. Никаких произвольных записей в заводские батареи. Ни speed write, ни рекуперация.

## Открыто
Рекуперация выключена до EM090 native brake proof. Заряд на ходу, окончательные параметры/КПД, UI шкала, более сложные смешанные/многосетевые сценарии, долгий 100-train UPS, Windows и MP не утверждены. Устаревший 0.1.99 эксперимент не принят. Main и owner 0.1.84 не менять.
