# 0.1.49 — план визуального развития ВСМ и подвижного состава

**Статус:** изучены исходники Base 2.1.24 и контракт спрайтов; [исследование](../research/hsr-rolling-stock-sprite-api-049.md). Следующий этап — художественная концепция и малый runtime probe. Без изменений игрового кода.  
**База:** принятая 0.1.48, main `111143dac62670f1e377a1288b58fb78eae78c75` (слияние PR #27).  
**Рабочая ветка:** `feature/hsr-rolling-stock-visual-049`.  
**Цель:** узнаваемый электрифицированный высокоскоростной путь и электровоз с живым косметическим пантографом.  
**Принцип:** графика не меняет физику, пропускную способность, коллизии, электроснабжение или текущую логику контактной сети.

## 1. Исходное состояние и ограничения

- В 0.1.48 приняты видимые пролёты, согласованные со связностью настоящих ВСМ. 16 PNG и калибровка опор заморожены; повторно не рисовать их без дефекта.
- В `ElectrifiedMainline/prototypes/bootstrap.lua` фактический электровоз `em-electric-locomotive` наследуется через deepcopy штатного locomotive, имеет `energy_source={type="void"}`, 600 kW, `max_speed=1.5`. Эти параметры и имя не менять. Существующие грузовые и жидкостные вагоны оставить без изменений.
- В `ElectrifiedMainline/scripts/control.lua` уже есть выбор наших локомотивов из поездов, обработка `on_train_created`, отслеживание скорости и диагностический поиск рельса. Изучить их перед добавлением отдельного визуального модуля; не регистрировать один event дважды.
- Собственная графика ВСМ должна покрывать все четыре уже используемых типа: straight, curved-a, curved-b, half-diagonal. Не менять существующие имена, геометрию рельса, маски столкновений, fast-replaceable_group, next_upgrade, слоты сигналов и Undo/Redo.
- 25 кВ — номинал; ни пантограф, ни искра пока не означают реальное питание. Фактическая изоляция заводской сети остаётся отдельным тестом.

## 2. Порядок работ

### A. Исследование и художественный тест (перед кодом)
1. Заполнить research record по шаблону проекта: точные версии Factorio, исходники Base и хотя бы один рабочий аналог пользовательских rail/locomotive sprites или анимируемого roof overlay. Изучить текущие прототипы и API на 2.1.24; не угадывать число направлений, размеры спрайтов, свойства graphics_set, ориентацию, render layer или параметры анимации.
2. Согласовать визуальный язык: технологичный, читаемый в масштабе Factorio, узнаваемая ВСМ; компактный кузов электровоза, пантограф различимый даже при отдалении. Первые сравнительные картинки/атлас — вне папки мода. Владелец выбирает дизайн до полного набора направлений.
3. Разобрать геометрию соединений рельсов, стыки, варианты балласта/шпал, тени и уровни отрисовки. Не подменять реальные rail sprites плоской универсальной картинкой.

### B. Графика рельсов
1. Составить карту всех native rail graphic layers/directions на основе фактического Base-прототипа. Изменить только визуальные данные существующих ВСМ; сохранить все четыре геометрии.
2. Подготовить PNG-ресурсы из согласованного исходника. Проверить альфа-канал, размер, отсутствие швов, непрерывность стыков и положение относительно опор.
3. Собрать CI-прототип, проверить straight/half-diagonal/A/B, переходы между типами, стрелки/пересечения, повороты, призраки, роботов и штатный Upgrade Planner/Undo/Redo. Если полный комплект рельсов требует большого объёма графики, выпустить отдельный визуальный этап и не подгонять механику под картинку.

### C. Кузов электровоза
1. Сохранить существующий prototype ID `em-electric-locomotive`, предмет и рецепт; заменить только согласованные графические поля, не добавлять второй функционально одинаковый локомотив.
2. Сначала один утверждённый художественный ракурс и совместимый масштаб. После утверждения — полный реальный набор направлений, тени, иконка, обязательная штатная цветовая маска (ручной цвет игрока и цвет станции), свет при необходимости. Колёса, сцепки и положение кузова сверить с native locomotive. Не менять physics.
3. Проверить движение в обе стороны, разворот, повороты, сцепление с вагонами, размещение в курсоре/призраке, загрузку старого сохранения. Никакого постоянного пантографа в кузове, если нужен отдельный управляемый слой.

### D. Пантограф MVP
- Отдельный косметический слой на крыше существующего электровоза (candidate: entity-attached LuaRendering sprite; API и поведение вращения/offset проверить на целевой версии до реализации). Предпочесть штатный анимируемый слой, если найден рабочий аналог, удовлетворяющий состояниям и производительности.
- Два состояния: стоит — опущен, движется — поднят. Определять движение по абсолютной скорости поезда, независимо от направления; небольшой порог/гистерезис подобрать экспериментом. Не привязывать рабочее состояние к реальным MW, которых пока нет. В MVP движение по ванильным рельсам не мешает поднятому пантографу; если владелец захочет ограничение только ВСМ, отдельно согласовать.
- Крыша и вершина токоприёмника должны совпадать по высоте и перспективе с уже утверждёнными проводами. Проверить все ракурсы, переворот локомотива, не только один северный кадр.
- Управление при постройке/удалении, поездных изменениях, сохранении/загрузке, смене конфигурации. Не оставлять плавающих render объектов. Не создавать реальную электрическую сущность. Обновлять состояние/ориентацию только когда нужно, с учётом кадровой плавности; профилирование нескольких/десятков локомотивов.
- Предполагаемые новые файлы (имена уточняются после research): `ElectrifiedMainline/scripts/pantograph_visual_049.lua`, отдельный модуль графических прототипов, соответствующие runtime PNG под graphics/, `tests/rolling_stock_visual_049.lua`. Старые модули провода не менять.

### E. Искра — после MVP, отдельный опциональный этап
Короткая редкая вспышка в точке контакта поднятого пантографа и существующего пролёта ВСМ только в движении. Не постоянный эффект. Проверить render layer, детерминированность multiplayer и лимит эффектов. Не выдавать декоративную вспышку за наличие напряжения. Без изменения энергии/скорости.

## 3. Границы 0.1.49 и тестирование

MVP: художественный образ электровоза, две хорошо различимые позиции пантографа, работа на прямой и поворотах, плюс согласованный комплект рельсов ВСМ или первый завершённый этап графики пути. Порядок выбран для сокращения объёма переделок; разделить на 0.1.49–0.1.51 при необходимости, не выпускать сырые активы. Сохранить штатную замену рельсов, старые предметы, существующие сохранения, контактную сеть и её реальные/ghost ограничения. Искра не блокирует MVP.

Acceptance checklist:
- [ ] Изображения утверждены владельцем на игровом масштабе.
- [ ] Все native sprite geometry/direction contracts проверены; нет старых/лишних PNG.
- [ ] Старая линия 0.1.48 визуально не изменилась.
- [ ] Электровоз стоит/едет/останавливается, меняет направление и проходит изгибы; пантограф без отрыва от крыши.
- [ ] Рельсы всех четырёх типов состыковываются; ghost/robot/Undo/Redo/upgrade не повреждены.
- [ ] Удаление и загрузка не оставляют render objects; тесты на нескольких поездах.
- [ ] Gameplay параметры прежние, никакой незаявленной электрофизики.
- [ ] GitHub Actions: Lua syntax, regression tests, image contract, package boundary; только CI-built inner game ZIP, отдельный QA atlas.
- [ ] Отдельный live test владельца и явное разрешение до merge в main.

Ветка и план созданы. Ни одного нового runtime файла/PNG или версии info.json ещё нет. Подготовку графики/кодирование начать после изучения и утверждения визуального образа; не выдавать plan-only ветку за готовый 0.1.49 ZIP.
