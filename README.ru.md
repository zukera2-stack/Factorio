> **Кандидат публичной беты 0.1.62 (21.11.2026):** интеграционный [PR #46 → `main`](https://github.com/zukera2-stack/Factorio/pull/46) включает исправленную энергосеть EM070 (нативный `electric-energy-interface` с `usage_priority="dynamic"`, 20 МВт, поддержка реверса). Проверка исходного игрового кода: [Factorio 2.1.24, 3/3 нативных сценария PASS](https://github.com/zukera2-stack/Factorio/actions/runs/44920768721); два закрытых энерготеста + 48 подстанций и 32/multisource/brownout PASS на локальном стенде. **Этот PR пока DRAFT и не слит; далее в документе содержатся исторические сообщения EM066/067 об ошибках, исправленных в EM070.** Изолированный канал Updater `test/updater-approved` **0.1.61 не изменён**. Публикация беты не гарантирует совместимость с любым старым сохранением/Bob's/MP; игрокам следует делать копии сохранений. [Подробности EM070](docs/research/25kv-dynamic-eei-070.md), [межветочная навигация](docs/CURRENT_WORK.md).

> **Электросеть EM067 — отдельная оптимизация планировщика:** при точном совпадении параметров сеть использует сохранённый расчёт, иначе проверяет маршруты заново. 1 675 дифференциальных тестов PASS, 48-подстанционный native стресс + EM065 с 8 аккумуляторами и сохранением PASS. Производительность на большой реальной базе ещё не подтверждена; потери буферов EM065/066 не исправлены, релиз заблокирован. Рабочая 0.1.61 не меняется. [Отчёт](docs/research/25kv-dispatch-cache-067.md).

> **EM066 — физически обоснованные потери при коммутации:** во время аварии энергия линии действительно может рассеиваться в дуге, но программный EEI-буфер **не равен** энергии электромагнитного поля провода. Для списания нужна измеренная причина и сумма. Демонтируемая подстанция по принятому правилу теряет свой запас; внешние аккумуляторы и другие станции — нет. На текущей 0.1.62 остаются 1,5 МДж необъяснённых потерь, релиз заблокирован. [Инженерная модель](docs/research/25kv-switching-dissipation-066.md).

> **EM065, исследование учёта энергии (21.11.2026):** тестовый источник с 700 МДж и **нулевой новой генерацией** подтвердил потерю 1,667 МДж при перестройках, из них лишь 167 кДж разрешено рассеять при удалении подстанции. Восемь внешних аккумуляторов сохраняются и после загрузки игры, проверены нативные ограничения заряда/разряда. **Остальные 1,5 МДж — реальный нерешённый дефект, эксперимент не выпускать в патчер.** [Отчёт](docs/research/25kv-closed-reservoir-065.md).

> **Правило демонтажа подстанции:** её собственный кратковременный внутренний электрический буфер при удалении безвозвратно пропадает. Энергия соседних подстанций и внешних аккумуляторов этим правилом не затрагивается. Нативный тест измерил 166,7 кДж у демонтируемой подстанции, однако остальная часть энергетического расхождения при перестройке сети ещё требует исследования; релизный тест остаётся заблокирован. [Решение и результаты](docs/research/25kv-demolition-energy-policy-064.md).

> **Этап EM064 (перестройка сети):** тесты удаления рельсов и опор, объединения заводских сетей и реального save/load прошли, но строгий энергобаланс выявил **потерю 1,667 МДж при шести перестройках**. Никакого создания энергии не обнаружено. Экспериментальная ветка `experiment/topology-lifecycle-064` **не готова к выпуску**, патчер остаётся на 0.1.61. [Подробный отчёт](docs/research/25kv-topology-lifecycle-064.md).

> **Эксперимент EM063 — использование буфера передачи:** скрытый буфер подстанции теперь может полностью отдать накопленные ~0,333 МДж после отключения генератора вместо потери половины. Работа с аккумуляторами на обеих сторонах, реверс и заводские приоритеты проверены на Factorio 2.1.24 (11/11 native PASS, 12 200 тиков). Это **не полноценный аккумулятор внутри подстанции**. Код хранится отдельно в `experiment/buffer-flush-063`, версия для патчера остаётся 0.1.61. [Отчёт](docs/research/25kv-buffer-flush-063.md).

> **Эксперимент 0.1.62 — оптимизированный распределитель энергии:** на 48 подстанциях минимальный тик улучшен с 26,325 до 1,928 мс; 7/7 нативных тестов PASS. До одобрения тестовая ветка Updater остаётся 0.1.61. [Отчёт](docs/research/25kv-dispatch-optimization-062.md).

> **Исследовательская 0.1.62 — равномерное распределение энергии.** В трёх изолированных сетях новая логика делит общий источник 20 МВт между двумя потребителями поровну (10+10 МВт) и перенаправляет энергию при отключении одного потребителя. Проверено **на реальном Factorio Headless 2.1.24**, 3/3 сценария PASS. Версия 0.1.62 **не выпущена для патчера**: твой Updater 1.1 продолжает устанавливать проверенную 0.1.61. Ничего вручную скачивать не нужно. [Отчёт исследования](docs/research/25kv-fair-dispatch-062.md).

> **Тестовая сборка Electrified Mainline 0.1.61 готова для установленного Windows Updater 1.1.** GitHub Actions [44875890182](https://github.com/zukera2-stack/Factorio/actions/runs/44875890182) PASS: официальный Factorio 2.1.24 проверил ZIP, 20 МВт и заряд/обратную отдачу. Ветка `test/updater-approved` обновлена для патчера. Закрой Factorio → запусти **свой прежний** `Update.bat` → пункт **1** (обновить), затем **2** (проверить). Патчер обновит три изменённых игровых файла; 83 PNG не менялись. Добавлена **только** команда `/em-25kv-priority` (выдели EEI/аккумулятор/подстанцию); новая схема приоритетов здесь не реализована. Сохраняй резервную копию карты. В `main` остаётся стабильная 0.1.56.

# Electrified Mainline

Мод для **Factorio 2.1**: высокоскоростные рельсы, опоры контактной сети 25 кВ и в перспективе электрическая тяга, аккумуляторы и рекуперация.

**Предыдущая стабильная версия (история) — 0.1.24.** Проверена пользователем в **Factorio 2.1.20 (build 87512)** на сохранении «ВСМ». Визуальная архитектура опор C уже объединена с `main` через [PR №8](https://github.com/zukera2-stack/Factorio/pull/8): видимая решётчатая стойка при установке, восемь автоматически ориентируемых консолей, цветные призраки, работа дронов и Undo/Redo, иконка из южного спрайта и ненавязчивые круглые маркеры. [Отчёт по тесту](docs/tests/catenary-mast-0.1.24-user-accepted-2026-11-15.md) · [ZIP 0.1.24 в GitHub Actions](https://github.com/zukera2-stack/Factorio/actions/runs/43748406702/artifacts/14175755233).

**Важно:** контактные провода пока **только изображаются**. Энергия по ним не передаётся (`transfer_MW=0`), электротяга, батареи и рекуперация не реализованы. Это принятая **визуальная веха**, а не завершённый мод.

Проверенная ранее версия **0.1.8** остаётся как историческая точка отката и доказательство штатного Upgrade Planner + Undo/Redo для прямых и двух типов кривых рельсов. Не все эти сценарии повторно регрессионно проверялись в 0.1.24. [Тесты 0.1.8](docs/tests/undo-0.1.8-2026-11-12.md).

## Идея мода

Проект развивается вокруг следующих возможностей:

- прямые, кривые и полудиагональные высокоскоростные рельсы;
- электровоз с аккумуляторным резервом;
- упрощённая игровая модель контактной сети;
- рекуперативное торможение;
- специализированный подвижной состав;
- локализация на английском и русском языках.

Это цели проекта, а не утверждение, что все функции уже работают. Реальное состояние реализации описано в [docs/STATUS.md](docs/STATUS.md).

## Разработка

Исходники находятся в `ElectrifiedMainline/` — это самостоятельная папка мода Factorio. Файл `info.json` должен оставаться непосредственно в её корне.

Перед выпуском новой версии необходимо:

1. Для каждой нетривиальной механики, проблемы совместимости или обходного решения скопировать [шаблон исследования](docs/PROTOTYPE_RESEARCH_TEMPLATE.md) в `docs/research/` и заполнить его до написания кода. Следовать [протоколу исследования аналогов](docs/RESEARCH_METHOD.md): изучить работающие ванильные и однотипные модовые прототипы, сверить API целевой версии и сравнить их с нашим исходником.
2. Проверить загрузку с базовой игрой и с предполагаемым набором дополнений.
3. Протестировать размещение и демонтаж объектов, создание поездов, объединение и разделение составов, сохранение и загрузку игры.
4. Собрать ZIP, содержащий **ровно одну папку мода** в соответствии с текущим CI: `ElectrifiedMainline/info.json` в корне архива. Workflow пакует `ElectrifiedMainline/` без двойной вложенности. Файл `info.json` не должен лежать непосредственно в корне ZIP без папки мода.
5. Синхронно обновить `CHANGELOG.md` и версию в `info.json`.

## Метод работы над модом

Для разработчиков и ИИ-агентов обязателен [регламент вклада](CONTRIBUTING.md) и [AGENTS.md](AGENTS.md): сначала найти рабочий штатный или однотипный модовый аналог, изучить исходники, сверить требования с официальным API целевой версии, сравнить с нашим кодом и только затем вносить минимальное изменение. Не угадывать флаги и не считать успешную сборку доказательством работы в игре.
